# Kamaen Info 核心玩法开发任务计划

版本：v0.2 Gameplay-First Plan  
状态：主线已收束为“电只供能，信息走晶体/共振/光/频率总线”。本计划按玩法密度排序，把最能验证模组独特性的系统放到最前面做。

---

## 1. 当前实现基线

当前 Java 侧仍是早期注册层：`KamaenInfo.java`、`Config.java`、`KamaenInfoClient.java`。已注册 `kamaen_crystal_raw`、`kamaen_crystal_tuned`、`info_probe`、`fractionating_tower`、`explosion_chamber_controller`、`black_hole_parser_core`，但尚未实现 BlockEntity、Data Component、配方类型、菜单、网络包和机器逻辑。

这意味着第一轮开发不应先做完整工程平台，而应做一个小而完整的玩法原型：玩家拿到不同卡玛恩晶体时，能看见它们的信息属性差异，并能通过操作改变这些属性。

---

## 2. 主线收束

当前主线：

```text
圆石频谱
-> 白噪晶种
-> 卡玛恩晶体
-> 向量爆破与力学合成
-> 共振调谐与信息读取
-> 掺杂晶片与光路工艺
-> 共振信息自动化
-> 全光计算：物理结构即模型
-> 世界底噪采样
-> 凝聚态费曼过程
-> 量子光学协处理器
-> 人造视界 / 黑洞 / 维度创世
```

明确删除当前路线中的电气计算硬件段：

- 不做电气 CPU/GPU/NPU 作为中游算力。
- 不把主板、机柜、芯片作为当前主线核心。
- FE/电力只用于机器供能、泵浦、加热、刻蚀、退火和执行器。
- 信息传递优先使用 `InfoSignal`、晶体共振、频率总线、光路和红石边界触发。

---

## 3. 玩法优先原则

第一批功能必须回答三个问题：

- 这个晶体和普通材料有什么不同？
- 玩家如何改变晶体里的“信息状态”？
- 改变后的信息状态如何影响后续机器、模型或算力？

因此开发顺序应优先做“可观察、可修改、可诊断”的系统，而不是先补齐大量材料表。

---

## 4. 开发批次

| 批次 | 目标 | 主要任务 | 完成标准 |
| --- | --- | --- | --- |
| G0 卡玛恩晶体原型 | 先证明晶体是信息材料 | 晶体 Data Component；tooltip；调试生成；信息探针读取晶体 | 同名晶体可拥有不同频谱、张量、应力、噪声、相干度 |
| G1 晶体观察玩法 | 让玩家看见差异 | 初级分光/探针 UI；频谱条、三轴张量、稳定度、未知字段遮罩 | 玩家能判断“这块晶体适合导波/稳谱/偏振/爆破” |
| G2 向量爆破原型 | 让玩家能写入晶体 | 爆炸室控制器；简化结构评分；方向/强度/波形参数；输出粗晶体属性变化 | 同一输入在不同结构下得到不同晶体画像 |
| G3 共振调谐原型 | 让玩家能调参 | 晶体干涉仪/频谱锁相；目标样本；调谐成本；失败/漂移 | 玩家能把晶体向目标频谱靠拢 |
| G4 信息读取闭环 | 让信息进入自动化 | `InfoSignal`；`IKamaenReadable` 白名单；探针台读取方块/机器状态；红石转换 | 探针读数可触发一条简单机器控制链 |
| G5 频率总线与缓存 | 让信息能组织 | 频率总线相邻网络；信号缓存片；拥塞/冷却/质量诊断 | 多个探针信号能汇聚到同一控制器 |
| G6 I 型力学框架 | 让结构成为玩法 | 框架成型、结构缓存、传感器/作用器评分、动态参数 | 玩家摆放结构能显著影响爆破和调谐结果 |
| G7 光路工艺铺垫 | 为全光计算准备材料 | 掺杂晶片、导波材料、阈值滤波片、探测结、相位调谐片 | 不引入电气算力，只产出光路元件和相干工艺能力 |
| G8 最小光学模型 | 把玩法最重部分前置验证 | 输入端口、波导、2x2 MZI、非线性介质、光RAM、输出探测器、结构编译 | 玩家能摆出一个小型“物理结构即模型”并得到诊断评分 |
| G9 宏观信息中心 | 扩展到长期采样 | 底噪谱仪、底噪数据库、信息中心控制器、采样缓存 | 玩家能长期采样世界底噪并反向优化工艺 |

## 5. 第一阶段实施建议

### G0.1 晶体数据

建议先实现一个最小 `KamaenCrystalComponent`：

```text
spectrum_signature
axis_tensor
stress
noise_index
coherence
specialization
generation_seed
```

`doping_concentration`、`background_noise_response`、`chi2_coefficient` 可以先预留字段或延后，不要阻塞第一版。

### G0.2 晶体 tooltip

tooltip 第一版显示：

- 频谱主峰：3-5 个离散频段。
- 三轴倾向：X/Y/Z 三个条形值。
- 应力稳定度：稳定 / 偏振 / 导波 / 破裂风险。
- 相干度：影响后续调谐和光路稳定。
- 未知字段：用“未解析”显示，留给后续探针/干涉仪解锁。

### G0.3 探针交互

`info_probe` 第一版先做两件事：

- 右键晶体：显示晶体画像。
- 右键可读方块：输出一个简化 `InfoSignal`。

这比先做完整 GUI 更快，也能立刻验证“信息读取是玩法核心”。

### G0.4 工程支撑

工程骨架仍要做，但服务于 G0-G2：

- 拆出 `ModDataComponents`、`ModItems`、`ModBlocks`。
- 只为已用到的系统补 datagen。
- 先保证现有 3 物品 3 方块不回退。

## 6. 模型与算力系统计划

模型/算力系统不走电气硬件路线，分三层推进：

| 层级 | 阶段 | 玩法 | 实现形态 |
| --- | --- | --- | --- |
| S1 信息模型 | G4-G5 | 信号读取、缓存、路由、红石边界触发 | `InfoSignal` + 频率总线 + 信号缓存 |
| S2 结构模型 | G6-G8 | 玩家摆结构，结构就是模型 | `FrameworkProfile` / `OpticalCircuitGraph` |
| S3 光学算力 | G8 以后 | 光路传播、相干能、光RAM 衰减、诊断优化 | 光控制核 + 光路组件 + 抽象结算 |

第一版“算力”不需要 CPU/GPU/NPU 数字，而是诊断这些预算：

```text
signal_quality
route_congestion
coherence_budget
optical_loss
shape_match
calibration_age
ram_state_life
```

这些指标直接连接玩家可操作的东西：晶体质量、结构拓扑、光路长度、调谐精度、相干能供应和读取次数。

---

## 7. 最小可玩目标

第一轮最小可玩目标不是完整科技树，而是：

```text
拿到晶体
-> 看见晶体画像
-> 用爆炸室改变画像
-> 用探针/干涉仪读取画像
-> 用读取结果触发一个红石或机器行为
-> 通过诊断知道哪里不稳定
```

完成这个闭环后，再扩展分馏塔、框架、多方块、光路和底噪系统会更稳。

---

## 8. 验收原则

- 每一批必须产生玩家可感知的反馈，不只增加物品。
- 电力只作为供能显示，不参与信息传递媒介。
- 诊断比失败提示更重要：玩家要知道是晶体差、结构差、频谱不匹配，还是相干度不足。
- 服务端只保存结构图、状态和抽象数值；视觉和高亮放客户端。
- 任何新 ID 进入实现前，先在物品/方块字典固定用途、状态字段和阶段归属。
