# R2计算专题：旧设计冲突与处理建议

> 2026-09-07阶段统合：当前取得条件、玩法、物料、板柜与运行规则见[R4完整阶段设计](R4_STAGE_DESIGN.md)。本文保留思想来源和局部推导；与R4冲突处以R4为准，旧四托盘/双视图入门不再并列执行。

状态：深化审核稿。依据用户本轮选择，提供详细玩法与具体任务演示，不进行Java实现。范围限定模型构建、EDA、主板/集群及相关数据时序；R1全局发展线保持。2026-09-07的R2.1设备/物品深化增加C23–C28，共28项；均为修订建议。

主要依据：[EDA设计](../Kamaen_Info_Computing_EDA_Design.md)、[硬件设计](../Kamaen_Info_Hardware_TechTree_Design.md)、[信息系统](../Kamaen_Info_Information_System_Design.md)、[Runtime完整路径](../Kamaen_Runtime_Infrastructure/Complete_Path.md)。旧稿标题中的“定稿”“暂缓”不能代替本次逐项判断；以下为本轮建议，不改原稿。

## 1. 需要保留的详细设计

EDA双视图、格点微结构、层与区域、真实掩膜/流片、封装端口、T0–T5时序、主板自由槽位、机柜个体状态、机柜族、服务资源池、参数空间、四类数据、通用模型组件、脚本编译、内外网、参数共享、模型模板和物理光学搭建均保留。

本轮不把这些压缩成“合成一个CPU→装一个模型→等进度条”。重点是为每套自由度明确作用范围、修改代价和观察方法。

## 2. 具体冲突账

| 编号 | 旧稿依据与冲突 | R2建议 | 对玩法的影响 |
| --- | --- | --- | --- |
| C01 | 信息系统§6、7.5支持可复制模型；§10.3又说光学方块拓扑就是模型 | 区分模型定义、物理实现、部署绑定；专用光结构是一个绑定实现 | 通用模型可搬家；专用结构需重新映射/校准，不能无代价变任意模型 |
| C02 | EDA§3原理图+版图；Runtime§3仅模块与总线归属 | 模块作为可展开宏单元；简版自动铺版图，手工改动同一份布局 | 入门模板保留，进阶布局真正影响资源，不出现两套独立芯片编辑器 |
| C03 | 模型空间摆方块、世界摆模型组件、EDA也摆功能块 | 三个入口分别编辑语义图、语义图的空间表现、器件布局 | 模型重排仅在明确布线模式下收费；芯片位置影响器件布线，不能双倍扣同一条线 |
| C04 | Runtime§10六种通用组件与信息系统§7.5算子/参数/反馈专用块并存 | 保留通用底座；算子、参数等是配置形态/模板，可有专用外观 | 模板可展开复用，避免每种神经网络再加一套不可编辑方块 |
| C05 | Runtime路由包含normalize/simple_math，信息系统算子也执行这些 | 路由只选目标/传引用；算术和变换归算子，快捷路由配置展开成显式算子 | 一次规范化只收费一次，不能用路由免费计算 |
| C06 | 信息系统可反馈/异步触发；编译要求拓扑排序 | 区分单次无状态数据图和跨步State/消息反馈 | 无延迟代数环报错；RNN/PID经状态寄存器合法，不因有环全禁 |
| C07 | 模型物品保存状态定义，也支持复制和训练；未明确运行实例 | 模型版本保存结构/参数/状态定义，运行实例保存当前State与游标 | 两台机器默认不共享隐状态；复制结构、权重、检查点是不同动作 |
| C08 | 参数共享、外部回写、后台优化器与在线推理并行 | 推理固定参数版本；训练产出新版本，校验后原子切换 | 不出现一次推理前半用v3后半用v4；回滚有明确对象 |
| C09 | 信息系统§10.3把分束对应broadcast/concat/residual | 光器件作用与张量语义分开，由编码/解码与实现模板证明对应 | 分束不凭空扩展张量信息；concat需独立通道/索引与缓冲 |
| C10 | 信息系统样例4通道直接连2×2 MZI | 输入shape和物理模式映射显式声明 | 四输入要四通道算子，或声明两组时分处理；不能靠名字自动对齐 |
| C11 | EDA禁止跨die主逻辑，字段又有mixed_node/storage/bridge | 制造域、功能角色、环境要求分轴；混合节点在板/封装层组合 | 存储可电/光实现，bridge不是万能免规则制造域 |
| C12 | F等级被同时当协议、频率、性能乘数；T等级又近似硬性配对 | F/T是能力标签；实际传输率/节拍/相位要求单独定义 | 低速可做流水；分组光纤不必全链路保持光学相位 |
| C13 | EDA用路径差判断同步；主板把所有多卡路径要求等长 | 同步/相干物理路径检查等长窗口；包网络检查时延/吞吐/重排 | 加FIFO修异步时序，不要求整个集群做一棵等长相位树 |
| C14 | 硬件§4.2用yield_factor持续乘算力，EDA§8流片又分档 | 良率决定产出分布；已测试裸片以实际能力运行 | 一块合格芯片不会因同批报废多而永远慢；缺陷导致的降频单独记录 |
| C15 | 算力公式随bit_width线性增长 | 固定精度/算子口径给吞吐；位宽增加容量/成本，吞吐由实现表决定 | 不能仅调64bit获得数倍所有任务速度 |
| C16 | Runtime§7以max(cpu,script,gpu)作service_ops | 保留不同资源维度，用具体算子后端需求排程 | 更多矩阵单元不能替代DNS/调度预算；内存不能靠算力抵偿 |
| C17 | 集群网络=min(端口和,交换容量)，忽略实际路径/争用 | 聚合只用于概览与候选筛选，执行在具体节点/端口/路径预约 | 第二台计算机可能更慢，搬运位置和拓扑成为玩法 |
| C18 | Runtime§6稳定度加权平均，fatal_fault只作为一项0 | 致命故障先硬排除；剩余状态再决定限额/降载 | 冷却良好不能抵消断电；一个坏柜不把全部健康柜拖成最低值 |
| C19 | EDA总延迟含网络/排队；芯片仿真也使用这一口径 | 芯片报告服务曲线与局部延迟，部署加入排队/网络且只算一次 | 同芯片换网络不会改写出厂画像；诊断可定位层级 |
| C20 | 任务重试、状态提交、执行器副作用没有统一完成点 | 计算结果与外部动作分离；State有单写入序列，动作带幂等编号 | 失败可重算纯计算；不重复送料/交易，不悄悄跳过RNN时间步 |
| C21 | 建议规模可超越，与服务器有限预算存在冲突 | 推荐规模供优化，实际执行仍有硬预算与背压 | 超量任务排队/暂停，不强迫服务器无上限求值 |
| C22 | “不做真实仿真”容易被解释为模型只做评分 | 器件物理用近似；有限模型必须实际计算输入输出 | 换权重/接线能改变结果，训练有真实损失而非挂机加等级 |
| C23 | EDA宏单元既是版图模板，字典§7的eda_module_plate又是实体输入；复杂制造§2.2、10另消耗晶片生成裸片 | 区分整片流片与模块装配；前者从基材制造微结构，后者装实际成品模块 | 保留两种制造自由度；不同时收一遍晶圆原料与已经制好的全部内部模块 |
| C24 | 字典memory_page、信息系统§4的参数晶胞/矩阵/库以及连续逻辑页混用“页” | 实体页载片提供测试容量；逻辑页分配其中；参数库管理实际存储/版本，工作缓存按部署位置占用 | 一份权重数据不能凭名称增加硬件容量；复制、驻留和远程读取都有明确位置与成本 |
| C25 | 字典/光学旧稿以calibration_token表达校准消耗，设备/映射的实际有效条件不清 | 改为绑定对象/设置/条件的校准凭证；消耗来自实际测量、能源和参考件寿命 | 复制卡片不校准新阵列，改光口/波段后定位需重测路径；固定等待不替代验收 |
| C26 | 字典component_item/block两用，通用封装芯片与角色名芯片并列 | 模块、测试座与封装保持同一物理组成账；角色名是能力/变体呈现，不能重算成品 | 取整机或拆内部件按实际回收；不会既掉整块芯片又掉完整免费内部件 |
| C27 | 信息系统参数空间/世界模型块可以复制封装，尚未明确图元与实体的转换边界 | 编辑空间保存定义；世界结构需要底座；工件导入先显示需放置实物，图元不能拿回背包 | 保留两种编辑方式与参数空间；复制模板不刷方块、存储或活跃State |
| C28 | 旧多工位、EDA、信息中心与光源的分散配方容易把首版所需控制/模板/记录依赖到自身成品 | 粗模板/模块装配、早期夹具、普通供能与空记录柜先自举，精密设备和模型反馈后升级 | 第一颗芯片、第一份数据、第一束可用光各有低阶入口；低阶能力不冒充精密工艺 |

## 3. 先定职责，暂不冻结接口字段

按用户最新要求展开的构建顺序：**晶体怎样成为器件 → 芯片如何设计与制造 → 主板/机柜如何连接与供给 → 集群如何组织节点 → 模型怎样由底层组件表达、算子怎样占用实际硬件。** 模型需求随后反馈下一轮硬件周期；首轮硬件用内置基准测试，不等待最终模型自举。

工艺制造影响实际硬件，硬件约束部署，部署成本促使玩家修改模型；模型结果又指导工艺。保存、编译、流片、校准、部署和训练不是同一个按钮。

R2只把这一职责和可见行为写具体。最终NBT/Data Component、Java类名、缓存实现和网络包结构，在玩法确认后按最小切片设计，避免再次先堆字段再找用途。
