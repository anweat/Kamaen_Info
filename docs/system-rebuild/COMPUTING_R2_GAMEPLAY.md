## 1. 玩家会经历的完整周期

```text
实际晶体批次 → 加工/测试为器件 → 器件库
→ 芯片原理图 → 微结构版图 → 规则检查/抽象试验
→ 掩膜 → 加工任务 → 裸片测试/分档 → 封装
→ 主板布局/制造 → 安装芯片/内存/接口
→ 机柜装配/布线/供电/冷却 → 节点压力测试
→ 注册机柜与服务 → 集群拓扑/调度
→ 通用模型组件 → 参数/算子/状态图 → 编译
→ 部署到具体设备 → 实际求值/训练 → 诊断
→ 修改模型、调度、主板或器件，开始下一轮
```

硬件第一轮使用自带的计数、向量运算和读写测试任务，不要求先造一套模型系统才能测试芯片。后续的真实模型需求再驱动第二轮EDA。这保留旧稿的完整硬件周期，也避免任何一侧等待另一侧自举。

## 2. 卡玛恩晶体怎样成为器件，而不只是配方材料

**旧稿依据**：早期晶体设计的应力/取向；EDA§3.2–3.3微结构；硬件制造§12；复杂制造参考的晶圆、封装、供能和热界面。

玩家从实际母晶切片，选择局部取向、掺杂区与退火路线，在器件测试台装入不同夹具。仪器给响应曲线、有效工作窗与误差，不给一个“晶体品质92所以所有芯片都+92%”的总分。

| 器件方向 | 玩家加工/测试的内容 | 下游确切影响 |
| --- | --- | --- |
| 电门控结/沟道 | 组成分区、控制端、接触、输入扫描 | 门限裕量、可靠节拍、功耗与失效窗口 |
| 导波/分束/相位单元 | 切片方向、路径几何、分束/相位扫描 | 路径损耗、可调范围、校准精度与漂移 |
| 保持/存储单元 | 写入、等待、多次读取、复位 | 容量、有效寿命、读写口与刷新需求 |
| 探测/调制单元 | 参考注入、量程、偏置、响应时间 | 电/光转换的精度、延迟和输入范围 |
| 稳谱/工程结构 | 温漂、加载、振动/冷却对照 | 节拍源、环境裕量、封装应力与维护周期 |

每个器件保存母批和加工后的实际状态，测试报告指向该器件/批次。装入芯片后，由器件和结构派生性能；替换一个关键器件会使相关路径校准失效。不会每次读tooltip都随机生成属性。

“器件库”同时展示标准设计模板与当前库存的实际器件。设计预览可用标准参数区间，流片/封装时必须消耗材料并绑定实际状态；设计图不会生成免费合格器件。模板在整片流片中形成待制造结构；库存器件在模块装配中成为实际输入，两条物料账分别预览。

**第一次选择**：把低漂移但门控较慢的晶片留给基准/保持，用高门控裕量片做控制，用低损耗片做光矩阵。副品不是只能丢弃，材料分档直接影响计算布局。

## 3. 芯片设计：原理图与版图是同一设计的两个层面

### 3.1 开始一张芯片设计

玩家在蓝图台选择制造域与测试任务，再选基底尺寸/层栈。电、光、量子是不同制造与环境能力；控制、矩阵、存储、桥接是功能角色，不混在同一个枚举里。首轮只展开电控制与经典光矩阵，保留以后量子器件库的位置。

原理图里先放：输入端口、ALU/MAC或MZI宏单元、寄存/缓存、I/O、时序和输出。连接显示数据宽度/类型与方向；端口未连、形状不匹配、跨域无适配分别定位。

模板是一组可展开元件。玩家能复制、重命名、封装子电路；折叠成一个宏单元不会减少面积、资源和延迟。自带4位ALU/小矩阵模板可直接使用，复杂布局不是首次通关必须完成的谜题。

### 3.2 切到版图视图

同一原理图生成待放置实例；每个实例有占地、方向、层需求与keepout。玩家放置并画电互连、波导、冷却和端口。自动铺设给可用起点，手动优化可获得更短路径、更少跨层、更好的热分布。

原理图与版图不能互不相干：增加一个算术宏单元，版图出现未放置实例；删除一条关键物理线，连通校验指出对应逻辑边失去实现。移动元件只改物理路径，不改变算术含义；改变连接目标则要求回到功能校验。

版图里的微结构是编译/工艺结算单位，不逐个在游戏tick里求解真实电磁场。几何改变会改变可解释指标：路径延迟、损耗、局部热密度、可用端口、最小间距与工艺容差。

### 3.3 四类检查各回答一个问题

| 检查 | 回答什么 | 失败示例/处理 |
| --- | --- | --- |
| 功能检查 | 图能否表达目标输入输出？ | 悬空端口、shape错、无状态组合环；修图 |
| 布局对应/DRC | 每项功能是否有合法结构实现？ | 未放实例、越界、错误跨层/弯曲、短接；移动或补线 |
| 工作窗/时序 | 能否在声明的节拍和环境下执行？ | 同步组延迟差、FIFO不足、相位漂移、刷新超时；降节拍/加缓冲/校准 |
| 测试任务预览 | 同一组输入会得到什么结果和成本？ | 功能不符、热预算不足、吞吐不够；查看逐项贡献 |

错误阻止导出对应工艺；警告允许制造，但列明降档风险或运行限制；建议不影响合法性。功能正确不代表制造合格，制造合格也不代表所有任务都划算。

### 3.4 保留T0–T5时序玩法

T0手动触发→T1低速节拍→T2窗口/FIFO→T3流水→T4相干/刷新→T5观测窗口，作为元件能力逐步展开。玩家实际摆采样门、同步FIFO、流水寄存、相位epoch标记、刷新调度器，而不只在属性栏把T1改成T4。

跨时钟域FIFO用于吸收时序差；光学相位路径用相位窗口/校准；分组网络用时间戳、队列和协议。三者不能用同一个“同步质量”相互替代。MZI的相位标定也不等于整个集群都需要相位锁定。

界面显示一条具体路径：源→本地处理→缓存→跨域→目标，标示设计窗口、估计延迟和最紧约束。玩家可以加流水提高连续吞吐，但同时看到单条结果延迟与缓存消耗可能增加。

## 4. EDA硬件周期：保存、流片、测试、封装与返修

```text
编辑草稿 → 保存蓝图版本 → 检查通过 → 生成掩膜集
→ 选择材料批次与工艺路线 → 预约设备/进料
→ 多步加工 → 裸片检测 → 分档/报废/返工
→ 选择封装 → 映射端口 → 封装后复测 → 可安装芯片
```

保存蓝图只保存知识；掩膜消耗载体；流片消耗晶片/处理剂/工艺能源；封装消耗实体结构。加工开始后固定蓝图/工艺版本，编辑新草稿不改变已在炉中的批次。

**另保留模块装配路线**：实际门/保持/光器件→EDA模块片或功能模块→按装配图连接→封装/复测。该路线消耗实体模块和外部连接/支撑；整片流片只按层结构消耗基材与工艺材料，不再收一遍已制模块。两者在封装、端口与能力测试汇合，详见[R2.1制造路线](COMPUTING_R2_CONTENT_PLAYBOOK.md)。

**良率与性能分开**：工艺条件决定一批有多少合格、降档或报废件；单颗成品以实际测试的可用功能、节拍与误差运行，不再额外乘一遍该批良率。缺陷可造成某端口不可用、可用面积减少或低频运行，须有具体原因。

封装选项保留DIP/QFP/BGA、光接口和其他专用封装，按端口、维修、热和成本选择。端口映射必须保留功能/载体/方向/吞吐限制，不能把输出引脚改名成光口就完成转换。

**返修规则**：软件任务/模型参数变化通常不用流片；校准漂移可重校准；封装可拆卸更换但有材料折损；修改实体结构/增加不存在的功能需新裸片或已声明可重构器件。旧版硬件仍能跑兼容任务，不自动报废。

## 5. 主板设计与装配：实际模块怎样接在一起

保留旧稿5×5/7×7/9×9槽位蓝图建议，具体尺寸待试玩。玩家布局插槽、内存控制器、数据/控制平面、供能、冷却、时钟与外部端口，然后制造空板，装入实际封装芯片。

板型是布局产生的用途，不是强行选职业：控制板偏I/O、存储板偏页槽/通道、矩阵板偏计算与本地内存、交换板偏端口和路由；混合板放不同域的芯片，通过明确桥接互连。

| 玩家选择 | 可见取舍 |
| --- | --- |
| 多插一个计算芯片 | 增加任务能力，也占供能、热、内存带宽与槽位 |
| 增加内存通道/参数库口 | 减少喂数等待，挤占计算/网络位置 |
| 放置电/光桥 | 增加后端可达性，也增加编码、校准、转换时间 |
| 改端口方向/加扩展背板 | 能接到机柜前面板，付出路径和槽位成本 |
| 改供能/散热结构 | 提高持续运行裕量，不能创造不存在的算子能力 |

装配后跑持续而非仅瞬时压力测试，得到**可用算子集合、各精度/shape吞吐、本地工作内存、内存/端口带宽、持续热限与控制预算**。这些能力来自实际芯片和连接，不让玩家手填“gpu_ops=10000”。

主板总线只核算板内流量，芯片局部成本和网络成本在各自层核算，不重复惩罚同一字节。通用主板与服务器机柜的适配用机械/端口/供电规格表达，允许转接方案，不凭“通用”名字永远禁止上架。

## 6. 机柜构建：把图纸变成可维护的设施

玩家在有限多方块框架装主板托盘、电源、交换/背板、冷却、前面板与维护通道。可用结构投影对照实际放置；背板只组织互连与共享设施，不直接赠送计算能力。

R2.1给出一个2×2×3、12个功能位置、4个主板托盘的小柜教学提案，并逐格列外壳与内件。它只提供首套可照建的模板，专用与高密度柜仍可扩展；首柜仅装一板即可自检。

装配过程有五个明确步骤：放框架→装板/存储→接电和冷却→映射板端口到面板→执行带负载自检。机柜能存多个板，但不是把它们所有内存自动合成一块本地内存。

首次机柜可只装一个板，复用单机已通过任务。后来增加计算柜、存储柜、交换柜、边缘接入柜；机柜族是组织/策略标签，同族也可能有不同器件与能力。

**每柜保留个体状态**：哪块板在执行、哪个端口拥堵、温度/功率/冷却余量、待维护部件、离线原因。集群概览可以汇总，但必须能点击“任务慢→某柜→某板→某端口/封装”定位。

致命故障先使对应执行域离线，不用稳定度平均把断电抵消。共享电源故障影响其实际供电范围，局部端口故障不随机宣布整个世界的集群坏掉。冷却恢复后按自检/降载策略重新接纳任务，已有持久档案保留。

## 7. 集群：总算力不是任务一定能用到的算力

玩家将已自检机柜接入交换设备，在编排台登记节点、服务、储存位置和资源配额。第一条路由使用直接地址；服务增加后再启用DNS/命名空间模板，不让域名配置成为第一次跑任务的障碍。

界面至少有三个视图：

- **实体拓扑**：机柜、端口、链路、共享交换容量与在线状态。
- **资源视图**：各节点算子/精度、工作内存、参数驻留、可用时段与热约束。
- **任务时间线**：上传、排队、校准、执行、同步、返回，绑定具体资源。

编排顺序：任务检查→筛可运行节点→检查本地内存→选择分片方式→计算数据/参数位置→预约节点及共享链路→执行→提交结果。资源池总和只用于概览，不能拿两张不相连的4KiB内存冒充单算子所需8KiB本地内存。

| 策略 | 真正怎样执行 | 玩家为什么会选 |
| --- | --- | --- |
| 本地执行 | 数据所在节点运行兼容图 | 单条低延迟控制，免传输 |
| 数据并行 | 多节点复制同一模型版本，各处理不同样本 | 大批互不依赖样本；代价是参数复制与回传 |
| 流水/模型分段 | 相邻子图固定在节点，传中间Activation | 单机放不下或专用后端分工；代价是层间流量 |
| 算子切块 | 某个注册算子支持矩阵分块/归约 | 单层大任务；必须有明确归约和精度语义 |
| 参数/数据就近 | 优先已驻留正确版本的节点 | 重复推理减少上传；训练更新可能使缓存失效 |

不支持切分的算子不能靠“集群总容量足够”强行执行。训练数据并行还要同步梯度/参数与优化器状态，不能把推理分片直接当作训练完成。第一版只做同步、版本明确的训练轮次，异步训练作为后续选项。

控制预算和任务预算分别显示；忙于路由/调度的节点不能无限维持全部服务。玩家设置优先级、截止期、微批量、节点亲和与内存/带宽上限，有默认策略，但不能手填突破实际硬件的吞吐。

## 8. 底层模型构建：少量组件表达很多模型

**旧稿依据**：Runtime§10通用节点、信息系统§4–8参数/算子/状态/触发/封装。保留参数空间和世界方块两种编辑方式，它们编辑同类模型定义；不让玩家重复抄两遍。

| 组件形态 | 玩家配置/接线 | 实际含义 |
| --- | --- | --- |
| I/O网关 | 绑定传感器/页/服务，声明shape、单位与时效 | 引入Input或导出结果，不含免费变换 |
| 数据/参数节点 | 填值、导入测量、绑定参数晶胞/矩阵板/库 | 保存常量或参数引用，四类生命周期明确 |
| 算子模块 | 选择原生运算，连接输入、参数和配置 | 实际运算；脚本或模板展开为相同算子图 |
| 路由节点 | direct、分支、广播、入口/出口、目标服务 | 选择目的地/传引用；算术变换另列算子 |
| 状态寄存节点 | 初态、复位、更新触发、检查点 | 跨次运行的State，显式打断反馈环 |
| 触发节点 | 输入到齐、定时、事件、上次完成 | 提交任务，不直接任意更新他人状态 |
| 编译/封装台 | 暴露端口、校验、版本、封装模板 | 生成可部署模型/模块，不制造算力 |

这些是玩家认知角色，不要求恰好注册七种新方块；旧六类通用底座可配置出这些形态。反馈节点是数据/评价模板外观，Normalize/reshape等是明确收费的算子，不能藏在路由里免费执行。

参数晶胞适合标量教学，矩阵板适合张量，晶体簇组织层，参数库管理版本/打包。运行时用连续缓冲与编译索引，不每tick扫描每个参数方块。参数空间只是可返回编辑场，不要求P27创世设施。

R2.1进一步区分实际存储载体与其中的逻辑数据页：`memory_page`候选为有容量/易失性/内容的实体页载片，参数节点可装介质或引用实际参数库。模板复制只复制定义，数据复制占目的地空间；运行时工作缓存另计。参数空间图元不能作为免费实体取回世界。

### 8.1 参数空间中的距离是否收费

普通语义编辑模式：方块/节点位置用于组织，逻辑连接定义计算，不因玩家把注释区放远就永久降低性能。部署按实际硬件路径收费。

可选结构实现模式：模型显式绑定一座实际光学结构/计算阵列，物理端口、波导与器件位置决定成本。移动实体结构需要重新验证/校准。切换模式是明确绑定操作；不能同时对编辑空间虚拟距离和同一条实际线重复扣成本。

### 8.2 算子怎样执行

首批原生算子：Add/Mul、MatMul、BiasAdd、ReLU、Compare、Reduce、Slice/Concat、Reshape、Cast、StateRead/StateWrite。每个定义输入形状、参数、精度、输出语义、可用后端及资源需求。后续Conv、Embedding、Attention、MoE、RNN/PID等是可展开组合或有明确语义的内核，不是一种模型专属万能方块。

MatMul输入`[B,in]`和参数`[in,out]`输出`[B,out]`；MAC工作量为`B*in*out`，这里只把一次乘加算作1个MAC，不混用FLOP。网络带宽用字节/tick，容量用字节或固定大小页，不能把这些量和MAC直接相加。

模型编译：解析作用域→类型/shape→参数与状态引用→单次数据依赖→状态边界→生命周期/工作内存→可用后端→任务计划。校验通过后才预约执行，超内存可缩微批量或换节点；不在运行一半时才默默丢数据。

### 8.3 跨步反馈、共享参数和嵌套

一个运行实例内，同一State有确定更新顺序。触发开始时读取状态快照，计算成功后一次提交下一版本；相同实例的有状态任务顺序执行。无状态样本可数据并行，有状态序列按序列键分配；迁移要带检查点与事件游标。

子模块共享参数须显式引用同一个参数库版本；默认复制产生独立参数。一次运行固定图/参数版本，后台训练生成候选新版本；验证通过在新任务边界切换，正在运行的任务用旧版完成。检查点另含State/优化器/游标，不能把“复制模型”默认成复制活跃运行实例。

## 9. 模型怎样映射到EDA器件

| 部署方式 | 模型与硬件的关系 | 修改代价 |
| --- | --- | --- |
| 通用执行 | 算子映射到电/光兼容内核 | 更新图/参数后重新计划；无需重新流片 |
| 可重构光阵列 | 某个矩阵算子映射为相位/差分编码和读出 | 写权重、占校准时间、绑定器件状态/精度 |
| 专用物理结构 | 多个算子或整段功能由固定拓扑承载 | 在支持范围内调参；超出功能/尺寸需改结构或新流片 |

光分束只是物理作用，不能无条件等价于张量concat、任意broadcast或residual。实现模板要说明通道/编码/参考和解码，输出需与目标算子在规定精度内相符。四个标量输入接2×2阵列要明确拆分/时分方案，否则报错。

把权重保存到模型物品，与把它写成某块阵列的相位设置是两件事。更换阵列、波段或相关晶体状态后，旧相位配置可能无效；模型数学参数仍可保留。这样晶体品质、应力、制造和校准一直影响模型执行。

`calibration_token`在R2.1建议改为记录上述绑定与有效窗的校准凭证。复制记录不能使另一块阵列合格；能源、参考件寿命、扫描和留出检验属于实际校准任务，校准台只在通过后发布新设置。

## 10. 训练、任务完成与故障处理

推理执行实际输入输出；训练在支持可微规则的算子上计算损失/梯度并更新候选参数。不可微或外部算子标明不支持反传或提供独立训练方法，不能默认所有脚本都自动可训练。模型结构探索/工艺RL沿用同一任务和数据接口，但分别验收。

任务状态对玩家显示：等待数据→计划→资源预约→装载/校准→执行→提交结果，另有暂停、取消、失败和超时。仪器数据不可用、资源不足、功能不支持是三种不同失败，不统称“算力不足”。

| 故障 | 处理 | 玩家可以改什么 |
| --- | --- | --- |
| 纯计算节点掉线 | 从有效输入/检查点重算未提交分片 | 换节点、缩批量、保留参数副本 |
| 光相位漂移超窗 | 标记相关结果无效/暂停，重校准 | 改器件/环境或校准频率 |
| 共享链路拥塞 | 排队、背压、截止期判定 | 改数据位置、批量、并行度或拓扑 |
| 持续过热 | 对实际板/柜降载 | 改冷却、布局、任务分配 |
| 有状态实例迁移 | 固定序列与检查点，禁止两个节点同时写同一State | 选单写节点/检查点策略 |
| 执行器回执丢失 | 查询动作编号，目标支持去重才安全重试 | 使用本地执行网关，不能盲目重复送料 |

模型输出先是带版本的建议/结果；执行器动作另经规则与联锁。任务重试不会自动重复外部动作，训练失败也不清除当前已验证模型。

## 11. 这部分怎样逐步开放

第一轮：晶体器件测试→宏单元芯片→一次流片/封装→单板/单柜基准。第二轮：通用模型组件与参数→一条实际推理→对照数据验证。第三轮：第二节点与光阵列→集群分片→传输/内存/校准诊断。第四轮：训练、参数版本、物理光结构绑定和高级EDA反向优化。

物理制造、硬件组织、模型表达都保留完整上限，但每次教程只增加一类新矛盾。任务演示用同一批晶片贯穿四轮，让玩家看到：不是某个“科技等级”变高，而是自己改变了哪条路径、哪种容量或哪份解释。

实现上先做纯数据规则/有限算子执行，再接游戏方块和编辑视图；不要一次启动全套网络、任意脚本、动态维度或真实电磁模拟。这里没有冻结Java接口，也没有声称已有可玩模组实现。
