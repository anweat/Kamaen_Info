# R2具体任务演示：从晶体器件造出一条分档计算线

> 2026-09-07阶段统合：当前取得条件、玩法、物料、板柜与运行规则见[R4完整阶段设计](R4_STAGE_DESIGN.md)。本文保留思想来源和局部推导；与R4冲突处以R4为准，旧四托盘/双视图入门不再并列执行。

本任务按用户指定顺序贯穿：晶体器件→芯片/EDA周期→主板/机柜→集群→底层模型/算子执行→反向优化。操作与界面是实现提案，非已存在的游戏截图。

2026-09-07的[物品/设备深化](COMPUTING_R2_CONTENT_PLAYBOOK.md)提供具体槽位、装配账、柜型与十个任务；[逐项目录](COMPUTING_R2_CONTENT_CATALOG.md)对应旧稿实体。本篇继续保留原离线演示配置，不能把其8 KiB内存和手设速率直接视为新教学模板的出厂能力。

任务目标：工厂已有自动扫测，玩家制造计算设施，读取晶片的四项测试特征，预测透过率与漂移，再将候选送去实测分档。预测只减少需要精测的样品，不能自动把低品质片改成高品质片。

## 第一幕：挑选晶体，得到器件能力

玩家拿到三类已加工母批：门控裕量较好、光学损耗较低、参考漂移较小。它们不是通用高/中/低品质顺序。玩家将母批分配到门控、导波和参考器件试制，分别测试输入扫描、直通/相位与保持。

测试台右侧显示可用工作窗，左侧保存母批与工序记录，中间曲线显示失配/过载区。玩家可以把不适合高速门控的片转做低速参考或维护节点，避免整批报废。

本演示允许玩家直接使用已经掌握的保守工艺窗口。研究过程不能被跳过为自动解锁，但量产时不要求重复完成所有实验。

## 第二幕：在EDA里做出第一颗可用芯片

先选择“向量乘加与读写”基准任务，不先创建最终预测模型。打开电芯片模板：输入/输出端口、MAC阵列、寄存、内存控制、I/O和节拍。进入版图，将计算区靠近本地缓存，端口放到将来可引出的边。

玩家第一次故意把输出端口留在封装不可映射的位置；DRC标出对应网络。修好后，发现两个高负载区紧邻导致持续热裕量不足。可移动阵列、增加热通道或降低节拍，各自改变面积/吞吐/成本。

```text
基准任务 → 原理图 → 版图 → 功能/DRC/时序检查
→ 版本E1 → 掩膜E1 → 选择母批 → 多步加工
→ 检测裸片 → 选合格件 → 映射封装端口 → 封装后复测
```

本幕选择整片流片，物料按晶片、掩膜、工艺耗材与封装计算，不重复消耗版图中每个宏单元对应的实体EDA模块片。R2.1另保留用实际模块装配的入门/返修路线。

假设这颗测试后的芯片在给定精度/工作窗提供32 MAC/tick。这个数来自所安装的器件、有效并行通道、节拍与测试结果，不是玩家填写的奖励值。具体工艺到数值的系数本轮仍未平衡；此处32是演示假设。

随后用相位阵列模板做光学矩阵芯片，经过相同设计/制造/检测周期；它有较高矩阵吞吐，但缺少独立完成所有任务的控制、非线性与持久存储。光源、校准和读出属于真实装配需求。

## 第三幕：装主板和第一机柜

玩家制造一张控制/计算板，装电芯片、8KiB演示内存、页读取接口、普通供电和冷却，并把I/O映射到前面板。KiB是本离线切片的缩小数据尺度，不是最终游戏容量上限。

单板先跑测试；放进机柜后连接电源、背板、冷却与外部端口，再跑同样任务。机柜没有直接加算力，但持续供能/冷却、端口与维护状态进入诊断。

第二类板装光矩阵、电控制/激活、局部内存和光电桥。桥接器空缺时，界面提示“输入无法编码到该后端/中间结果缺少读出”，而不是在任务结束时随机失败。合格后成为演示中的128 MAC/tick混合节点。

两种机柜在面板上的角色不同：本地节点靠近传感器，混合节点适合批量矩阵。每个柜、板、芯片、端口都能点开，不压成一个“总算力160”的黑箱。

## 第四幕：把机柜注册成集群

玩家连一条共享上行和交换端口，把两个混合节点注册到编排台。为后续任务设置：允许节点、每节点内存、总链路预算、是否保留参数和故障策略。先用直接地址，不强迫先配置完整DNS。

界面展示实际拓扑：数据在本地柜，两个远端柜共享一段64 B/tick演示上行。两个网口各写64不代表共同上行有128；打开链路详情可以看到共享关系。

现在集群已经能运行向量/读写基准。接下来玩家构建真正要用的模型，让这些能力服务晶体工艺。

## 第五幕：用底层组件搭模型

在世界模型组件或参数空间里创建图，输入四项归一化特征：低/中/高频段响应与标准工况下的应力响应。原始测量与校准版本保留，归一化过程可展开查看，不能从隐藏晶体真值直接填输入。

```text
输入网关 X[B,4]
      ↓
MatMul ← 参数矩阵 W1[4,8]
      ↓
BiasAdd ← 参数向量 b1[8]
      ↓
ReLU
      ↓
MatMul ← 参数矩阵 W2[8,2]
      ↓
BiasAdd ← 参数向量 b2[2]
      ↓
输出网关 Y[B,2]：透过率预测、漂移预测
```

这不是直接放一个“神经网络方块”。玩家放参数板、算子与网关，拖线声明引用，然后将两段Linear封装为可展开子模块。模板模式可以自动放这些内容，但底层仍能查看/编辑。

玩家把W1误设为[8,4]，编译器在第一条MatMul连接指出“4个输入特征与权重第一维8不符”，同时显示实际期望。调整矩阵或明确增加转置算子，不能靠改名字消掉错误。

保存M1模型版本，参数58个。演示按float32容量口径需232 B；参数晶胞/矩阵板可显示为不同外观，保存后打包到缓冲区，不要求运行时扫描58个方块。

**实际前向例子**：固定候选参数下，输入`[0.8,0.2,0.5,0.1]`得到`[0.699,0.195]`；只把第四项改成0.9，输出变成`[0.635,0.359]`。这些结果由[离线脚本](computing_r2_demo.py)真实求值，不是预设“完成后加分”。参数为示例，未训练，也未证明对应真实游戏材料。

玩家可先将“预测透过率≥0.65且漂移≤0.25”作为候选筛选规则，随后进行实测。前者进入精测队列，后者转去其他用途或复核；这些阈值也仅供示例，不作为最终品质判据。

## 第六幕：部署时才决定在哪里算

模型编译输出算子、数据shape、参数版本、工作内存、后端兼容性和阶段依赖。玩家展开部署方案，看到第一层/第二层乘加分别落到哪块芯片，ReLU/BiasAdd由哪块电逻辑执行，Activation是否要出板。

模型不因部署到光节点就改数学定义。光阵列映射需要编码、相位设置、校准与读出；两层之间的电激活造成额外内部转换。校准后的误差若超过任务容限，应拒绝该后端或降级，不能只提升速度而忽略结果。

先执行64件一批：两层总共3072 MAC。保守预约输入1024 B、隐层2048 B、输出512 B、参数232 B和512 B演示工作区，总4328 B。

因此4KiB单节点容量不够。集群有两台4KiB，并不自动让单个未切分任务得到8KiB；玩家必须把64件分成两批32件，或选择可明确分块的计划。每批32件保守预约2536 B，可以运行。

## 第七幕：看见加机器的收益和代价

下表由同一个成本脚本生成，使用公开、可修改的游戏假设；阶段按屏障保守求和，不是实际游戏服务器性能。

| 方案 | 演示耗时 | 玩家从中看到什么 |
| --- | --- | --- |
| 本地电节点，64件 | 121 tick | 算术较慢，但数据不出本地 |
| 单混合节点，冷启动 | 116 tick | 矩阵更快，上传/校准/转换抵消大部分收益 |
| 双混合节点，共享64 B/tick | 98 tick | 样本分片有效，但共享上行仍限制收益 |
| 双混合节点，共享16 B/tick | 191 tick | 增加计算机反而更慢，瓶颈在数据通路 |
| 双混合节点，上行升级256 B/tick | 74 tick | 改真正瓶颈才产生明显收益 |
| 本地仅4KiB，改两批32件 | 124 tick | 缩批量可避免换硬件，付少量调度开销 |
| 单件本地 | 7 tick | 适合低延迟控制 |
| 单件远端，冷启动 | 40 tick | 大机器不一定适合小任务 |
| 单件远端，参数已驻留且校准有效 | 21 tick | 缓存有收益，但固定通信时延仍存在 |

诊断时间线可点击：排队→输入上传→参数装载/校准→矩阵/电激活→结果返回。完整阶段数值、四组实际前向结果和假设见[可复算数字](COMPUTING_R2_NUMBERS.md)。

**第一个优化**：玩家选择将矩阵权重驻留远端，并给晶体扫描合批；每件待处理片仍保留ID，不能因为批量而交换结果对应关系。材料类别变更或重新训练后，参数版本改变，需要装载新权重；相位校准是否仍可复用由器件/后端明确判断。

**第二个优化**：持续观测输入来自边缘节点，将低延迟控制保留本地，历史批量预测发到混合集群。分工来自任务性质，而不要求全厂升级后只能用光学。

## 第八幕：训练、错误与第二轮硬件周期

玩家将实测透过率/漂移与预测对齐，形成按母批分开的训练/验证/终验数据。加入损失算子、优化器任务和参数库，产生M2候选参数版本；当前工厂继续用M1。

验证M2的未见工况误差和实际筛选收益，合格后在任务边界切换；旧任务用M1完成，新任务才用M2。若做数据并行训练，梯度汇总/参数一致性/优化器内存必须列入任务，不拿上面的推理时长冒充训练成本。

玩家还可试量化、小隐层、不同特征，观察误差/容量/速度三项变化。不会把“参数更少”自动认定成更好，丢失关键测量通道可能让模型更难区分材料。

如果矩阵已经很快，瓶颈转到桥接/内存，玩家回EDA修改主板通道或设计新的读出/激活芯片；只有物理结构真的改变才进入新流片。只更新M2权重时不消耗新裸片，但会消耗装载/校准和训练预算。

最后故障演练：关闭一个计算柜、制造旧参数版本缓存、断开结果返回链。无状态分片可重算；结果提交去重；外部送料动作须由带编号的执行网关单独完成。已加工的物料不能因为计算重试再被送一次。

## 本任务的审核点

本演示让晶体质量、芯片功能与布局、EDA制造、板柜连接、集群路径、模型结构、参数版本和实际算子计算都有各自可操作的影响；它们通过同一批样品相互反馈。

已做：固定小模型真实前向、保守容量/传输/成本核算、11项离线反例检查。未做：模型训练、真实器件误差、温升/故障调度模拟、游戏内GUI/制造流程、网络实现和试玩平衡。训练与故障段是详细行为提案，不是已运行功能。
