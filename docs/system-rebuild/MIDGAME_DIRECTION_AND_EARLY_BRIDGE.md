# 中期定位与前中期衔接：把工坊接入计算与信息中心

2026-09-07。**第1节保存本轮用户明确的方向；第2–7节是据此整理的衔接提案，继续讨论，不视为机制定稿。** 本文补充E1与R4之间的发展动机和能力交接，不增加正式科技编号，不变更现有B01、光模块、机柜预算，也不代表已实现玩法。

2026-09-08续议：用户确认从传感器与仪器出发，按科技和工艺发展设计可复用传感器，以数据和模型比较工艺方案。具体见[传感器、仪器到集成电路](EARLY_MID_SENSOR_TO_IC.md)：补充旧稿引用、测头制造、校准、级联逻辑与制造迁移；其中结构和数值仍为工作候选。

## 1. 已确认：中期究竟要让玩家做什么

本轮用户表述的核心是：**“将前期阶段的各种工具技术和内容信息化，模型化到我们构建的计算和信息中心中，以实现批量研究和量产。”**

1. 前期已经存在的加工、生产、探测和控制逐步接入计算机，由计算机管理复杂控制、重复分析和多设备协作。物理设备继续实际加工和执行，计算中心负责组织这些能力。
2. 材料、结构、历史与环境共同影响过程和产出。玩家通过观测建立模型，拟合这些关系，并根据实际误差改进模型、增加环境感应，或组合不同层次的模型。卡玛恩晶体自身的物质模型与世界底噪模型贯穿研究。
3. 学习对象不限于工业与科技：生物行为逻辑、Minecraft中的特性和过程、物流与环境变化，都可以形成从探测、记录到训练、验证和应用的玩法。
4. 构建和探索现实中的模型、算法与架构，本身也是中期目标。玩家既可以用模型解释世界，也可以研究一个模型怎样表示、记忆、计算、学习和协作；这条内容不要求每次实验都立即提高产量。
5. 计算与信息中心沉淀数据、模型、工艺和实验能力，让研究能够批量进行，让已经掌握的生产能够规模复制。前期成果持续发挥作用，并成为新的研究对象。
6. 这些设施为后续微观、宇观两线提供物资和计算基础。更大的算力支持更多对象、更长记录、更复杂模型和更高阶实验，同时也要求更好的仪器、材料、供给和工程组织。

共同主旨仍是**信息与频率**：卡玛恩晶体使原本难以辨认、传递和干预的差异变得可用；玩家将差异记录成信息，将信息组织成解释，再用解释设计行动与新实验。物性、频谱、时序、相关和语义共同参与，不把“频率”简化成一个通用加成值。

为避免后续同一个“模型”同时指代不同东西，记录中使用以下区分：

| 层次 | 在游戏里是什么 | 怎样变化 |
| --- | --- | --- |
| 世界过程规则 | 材料、环境、装置及Minecraft过程实际怎样演化 | 由实际状态和作用决定；训练参数不能直接改写它 |
| 观测与数据集 | 仪器、操作日志、实际检验与行为记录 | 改进采样、校准、覆盖和标注；始终可能不完整 |
| 玩家模型 | 对响应、状态、行为或结果的可执行解释 | 手工建模、拟合、训练、比较或组合，得到有适用范围的版本 |
| 控制与实验方案 | 如何使用模型、规则和目标选择下一步行动 | 提出可执行工单或设定值，由实际设备完成并回报 |

直接学习行动策略也是合法路线；上表不要求所有玩法都先训练一个世界预测器。它要求玩家知道自己正在解释结果、估计状态，还是选择动作。

## 2. 接续提案：过渡应发生在同一座工坊里

前中期的变化可以表现为同一套设备逐渐具备四种能力：**可测量、可留档、可调用、可组织研究**。每次升级都解决玩家已经遇到的重复工作，同时留下下一阶段能继续使用的实物与记录。

```text
前期实际生产、环境观察、行为观察
  → 把变化转成可比较的信号
  → 把信号连同条件、操作和结果留下来
  → 用有状态的控制组织一台设备的步骤
  → 用可编程计算复用同一套控制与分析能力
  → 单节点信息中心：数据、模型、工单和结果相互关联
  → 多设备、多地点、批量实验与模型架构比较
  → 机柜和集群支撑更大的研究及生产
```

记录和初步建模从前期开始；单节点也能训练小模型。机柜、联网、光电协作与研究能力可以交错建设，不要求先造完双柜才首次学习，也不把全部前期应用变成必修作业。

### 2.1 晶体响应怎样逐步走到可编程计算

| 玩家遇到的问题 | 用已有技术做出的下一步 | 当场看到的反馈 | 留给后面的能力 |
| --- | --- | --- | --- |
| 同一温程处理不同晶片，结果并不相同 | 用参考片、可调激励与读出观察目标响应 | 相同设置下出现可重复差异；换参考、方向或环境可以做对照 | 带条件的信号与校准记录 |
| 需要在响应进入窗口时行动 | 把晶体响应接入有供给的阈值、恢复与执行结构 | 连续读数被转换为明确条件；边界附近可见不确定区 | 可用的条件信号和控制接口 |
| 一个条件还不足以决定动作 | 拼接已验证通道，组合“样品有效且进入窗口”等条件 | 单件通过而串联失败时，能定位量程、驱动或时序失配 | 能级联的门与接口约定 |
| 一次短暂读数会误触发，换批又需要重来 | 加入保持、复位、节拍和计数 | 短脉冲被排除；连续有效窗口才通过；新批次清状态 | 有状态的工艺控制器，完成R4“三帧回声” |
| 每换工艺就重接结构，记录也难以批量比较 | 用选择、寄存、数值编码、计数/累加和有限步骤表复用硬件 | 更换步骤表即可运行另一套已支持的流程；精度与存储限制可见 | 可编程控制与最初的数据处理 |
| 多组数据、多套候选模型需要反复计算 | 将已验证控制、寻址、存储和算术模板组织为B01 | 同一块板能执行不同工艺程序和有限算子图 | 第一座本地计算与信息中心 |

“三帧回声”因此是入门逻辑的综合作品，不是第一次接触晶体后就要求完成的基本器件。其批次、有效性、连续窗口及炉端执行规则仍采用[R4总案第6节](R4_STAGE_DESIGN.md)。

可编程计算之前，还需要一个可见的小练习：将有限量程读数编码为有限位数，存入指定位置，读回并累加，再按步骤表重复。玩家能观察舍入、容量和顺序怎样影响结果；随后使用验证过的算术模板进入B01，不要求手工铺出整台CPU的全部门。

这一段不将已有红石或固定控制器作废。它们可以完成初始控制和对照。晶体方案的收益来自调谐、传感结合、通道组织、可复制器件及后续密度，不能只靠排斥原版能力制造需求。

### 2.2 性质到门控之间仍需单独设计的实验

第一步可先保留一个很直观的台上候选：固定频带激励经过晶片，加载夹具改变晶片响应，读出端显示通道通断趋势。控制动作通过真实加载器与能源完成。它展示“一个输入可以改变另一路信息的通过条件”，此时还不能直接宣称已得到可靠逻辑门。

随后比较两条可制造路线：保留外部加载机构的粗控制单元；用组成特化、局部控制区和接触结构形成更紧凑的受控响应。后者必须先测出控制输入与响应的关系，沿用[R3性质与制程](COMPUTING_R3_PROPERTIES_AND_PROCESS.md)中供给、恢复、工作窗与制程的要求，不能凭“N/P晶片”或“非线性”名称直接赋予逻辑功能。

真正进入逻辑拼接的验收，是输出能够在登记负载下驱动下一件器件，且低/高区间、恢复能力和延迟可测；反相需要实际反相或互补结构，保持需要可验证的状态机制。具体区域材料关系和制程窗口仍待这一轮逐步深化。

EDA从这里自然出现：保存成功结构、比较输入输出、替换器件、检查接口、复用模块和复测封装。封装先解决固定、接触和复制；缩小尺寸还需要相应制程，不能把台上大装置一键压成微小裸片。

### 2.3 光学与上述过程并行

晶体测量本身就给光学入口：观察透过与方向差异，组织导波与分路，比较两条路径，再在满足光源、参考和探测条件时研究相位与干涉。电控制负责扫描、读取、记录与反馈；光组件改善某些测量、通道组织或计算任务。

因此第一座中心可以接一条台上光路，之后才把合适功能整合进B02。初级光模块仍是经校准、有范围的特定映射，不能因为“光参与了信息”就自动支持任意模型。

## 3. 连续任务提案：《同一座工坊的第二种工作方式》

仍沿用已有晶片处理工位，不增加一排替代机器。旁边保留同批参考片和实际成品检验手段。

1. **记录差异。** 玩家按现有工序做几批，记下投料与处理历史、过程读数、可测环境和实际检验。固定温程能够生产，但不同批次存在偏差；差异来自过程模型与测量，不额外掷一次“学习需求随机失败”。
2. **让装置判断。** 先建立能稳定级联的窗口判断和状态控制，再验证“三帧回声”。它解决一种重复操作，尚不会预测所有材料，也不需要先训练模型。
3. **留下完整一批。** 将样品编号、当前作业、取样时刻、读数和结束后的检验关联。工程册先人工留档；自动写入需真实记录接口和载体。只装探头只能看到读数，还不能自动知道哪组操作导致了哪个结果。
4. **把经验变成可检验预测。** 先用前期已有曲线或简单拟合预测下一批结果，在新母批上比较预测与实际检验。模型输入只使用当时已经取得的信息；目标结果来自完成后的检验。
5. **让偏差提出新问题。** 如果模型在冷机时有效、连续工作后偏离，玩家可以比较测温、工作时长、材料批次等解释。补传感、换特征、增加历史状态或改模型结构，都应有对应证据，不能固定提示“升级神经网络”。
6. **接到第一块计算板。** 导入旧记录、工序卡和简单模型，先批量计算与比较，再把验证过的输出转成现有设备支持的工单或设定值。自动工单沿用人工实验的物料、加载、冷却与收料过程。
7. **从一批变成一组研究。** 玩家设定目标、变量范围、实际材料和可运行次数；中心组织多组对照，登记数据并比较模型。最初可以由玩家换样，随后接入现有送料与装配能力，逐步获得无人连续研究。

故事笔记候选：

> “起初我守在炉边判断一次变化。现在，我把判断的条件和留下的误差一并交给了机器。它能替我重复许多次，却仍需要我决定下一次要比较什么。”

## 4. 旧设备接入中心时，应交付什么

| 接入内容 | 从前期已有内容取得 | 让中心获得的能力 |
| --- | --- | --- |
| 观测通道 | 探头、参考、读出、校准和实际接线 | 取得带单位、方向、时间、有效性的测量；看不到探头未测的内部字段 |
| 对象与作业记录 | 样品、母批、工序卡和设备当前作业 | 将过程与结果关联；避免把别批、旧样本或重播记录混成新证据 |
| 可执行动作 | 已有供能、加载、送料、温程及局部控制 | 调用设备实际支持的步骤和范围；不通过模型输出直接生成成品 |
| 实际完成回报 | 冷却、检验、收料、失败/暂停记录 | 区分“命令发出”“动作完成”“产品取得”，形成可信标签与库存结果 |
| 可复制方案 | 已验证结构、工序和程序版本 | 在具备材料、工位、接口与资源的设施上重复执行 |

接入可以分次做：先观察，再留档，再调用。旧机器继续可用；新增的是所缺的探测、记录或控制适配，成本和物理接口要可见，不设置一个万能接头免费补全所有能力。中心提出批次安排和设定值，本地控制器保留必须就地完成的节拍、互锁与停止动作。

统一面板随能力逐步展开“设备 → 本次作业 → 记录 → 模型 → 研究计划”，沿用[R4统一入口](R4_UNIFIED_WORKBENCH.md)。这些是同一项目中可互相追溯的视图；生产设备、记录服务与计算节点仍是实际对象。

## 5. 从探测到训练，不只有工厂这一种题材

| 研究对象 | 从前期带来的内容 | 中期可做的研究 | 可得到的成果 |
| --- | --- | --- | --- |
| 晶体及制造 | 参考片、响应曲线、工序与成品检验 | 比较组成/结构/历史解释，预测工况，安排新的对照 | 工艺窗口、控制方案、材料与底噪模型线索 |
| 生物行为 | 可见行为、位置与时间，玩家实际实施的条件变化 | 比较条件反应、事件顺序与带记忆的行为模型 | 行为预测、布局或饲养策略、对既有机制的解释 |
| Minecraft过程 | 可观察状态、事件和玩家操作记录 | 推测过程依赖、时序和条件；在新场景验证 | 过程模型、自动化方案和可复现实验 |
| 环境与物流 | 探针、路径、负载、碰撞及作业记录 | 多点关联、路线/条件比较与动态调度 | 环境感应、设施布局和生产组织改进 |
| 模型与架构本身 | 已实现算子、状态、参数与可用数据 | 改变结构，观察信息如何流动、保留和更新 | 可复用模型模块、运行对照、计算工程经验 |

观察行为不等于直接获得生物AI内部状态；记录原版过程也不等于读取隐藏随机数或未来结果。规律可以是概率性的，研究结论保留版本和适用条件。相应应用边界继续遵守[E1.2应用模型](EARLY_E12_APPLICATION_MODELS.md)。

模型结构研究允许使用明确标识的自建规则数据、合成任务或已采集数据。合成任务适合比较“有无记忆”“不同聚合方式”等问题，但其成绩不能当作世界实测证据。先给出有限、可运行的算子组合，再逐步引入现实模型架构的教学版本；具体架构与真实理论的对应另行调研和设计。

## 6. “更好的模型”怎样产生持续玩法

改进路线至少有四种，不固定为参数量升级：

- **补观察**：增加真正缺失的环境或状态代理量，改善校准、取样时机和覆盖。
- **改解释**：在简单曲线基础上加入有证据的交互、时间历史或空间关系，比较适用范围。
- **组合模型**：例如已知工艺关系加残差预测，或先估计不可直接测得的状态，再由控制器决定动作；每层输入、输出和验证对象明确。
- **改运行与结构**：比较不同算子组织、模型架构和部署方式在误差、数据需求、延迟与资源上的表现。

环境影响同时进入真实过程与观测条件；玩家模型只能使用已经获得或明确估计的信息。所有候选在新批次、新时段或目标场景上比较，旧的简单模型也留作基线。更复杂的模型可以学得更好，也可能过拟合、来不及执行或需要尚未具备的数据。

频率在这里有具体用途：选择要测的谱带，区分混在一起的信号，比较幅相与时序，判断漂移和相关。信号载频、采样频率、控制更新频率和算子吞吐分别显示；生物行为和事件语义不强制编码成物理Hz。

算力需求从实际工作长出来：同时服务更多工位、保留更长历史、比较更多模型、处理更多通道、运行更复杂实验。设备不能观测到的差异不会仅靠增加机柜变成数据；生产扩张、测量进步和计算扩张互相支撑。
