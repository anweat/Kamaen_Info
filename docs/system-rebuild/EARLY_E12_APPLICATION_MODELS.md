# E1.2：原版增强、矢量作业、环境与培育的应用模型

2026-09-07，随玩法继续深化的模型候选。入口：[应用发展线](EARLY_E12_APPLIED_PROGRESSION.md)。沿用[E1晶体状态](EARLY_E1_CRYSTAL_MODEL.md)、[E1.1过程模型](EARLY_E11_MECHANICAL_SYNTHESIS.md)及[R4运行与研究](R4_RUNTIME_AND_RESEARCH.md)，不另建一套与物质/硬件无关的技能加成。

## 1. 同一模型怎样延伸到不同玩法

| 应用 | 权威实际状态 | 过程/动作 | 玩家获得的知识 | 最终用途 |
| --- | --- | --- | --- | --- |
| 锻造 | 材料区域、几何、界面、损伤/耐久 | 成形、调理、磨制、装配、使用 | 试件对照、工具用途报告 | 战斗、采掘与工艺工具 |
| 量产 | 各库存/在制品、机台状态、真实订单 | 送料、加工、移交、合成、回收 | 合格产量、瓶颈与缺料原因 | 建材/消耗品备料 |
| 矢量作业 | 位置、速度、承载/接触与供给 | 有作用范围的加载、导向、牵引 | 轨迹、到达与堵塞记录 | 搬运、施工与移动设施 |
| 环境探针 | 已登记环境源/原版公开状态 | 被动观察或实际主动激励 | 带时空/仪器条件的观测和估计 | 选址、干扰诊断、调查 |
| 培育 | 实际培养物、基质/库存、生长与环境 | 补给、保持、调节、收获、留种 | 同批对照、预测与策略报告 | 有机材料、农场和生物研究 |

每类分别保留真值、观测和玩家模型。反馈所用观测应有有效期和来源；界面不能一边声称仪器未知，一边把对应内部量直接当作模型标签。

## 2. 锻造模型：物性、几何到工具用途

### 2.1 加工对象与工具结果

```text
ToolWorkpiece
  材料族与实际用料、刃/背/柄等区域、接触界面、几何
  相态/结构/缺陷、工序历史、实际磨损/耐久

ToolUseProfile
  工具族、适用目标、基础采掘/战斗能力
  几何/材料状态导致的受限速度、耐用与作用差异
  已测使用范围、报告来源、规则版本
```

工艺更新工件，用途计算再把它映射到Minecraft中的动作。刃部接触与局部承载、柄部结合、质量/几何分别影响对应表现。对首种金属使用受限材料模板，先做少数可解释取舍，不要求立即模拟全部真实冶金。

首版至少提供三种可选规格：通用可靠、轻快精细、较强单次作用。它们应有不同几何和工序需求，不能只是同一个物品把全部属性同时加高。基础合格规格尽量提供明确保守模板；更复杂试制才承担更多不确定结果。

晶体工装通过激励/温程控制和测量帮助复制工艺。工具本体可选的晶体组件另有实际作用端与供给；一次主动效果的功耗、有效目标及冷却来自该组件，不能通过更名或换槽恢复库存。

### 2.2 原版衔接约定

本轮倾向采用“模组工艺工具＋声明的原版动作兼容”，先避免直接全局重写每一把原版工具。既有原版物品正常使用，导入加工或升级时再建立明确映射；注册方式待原型确定。

- 工具材料/用途层级与工艺差异分开，铁质工具不因一个工艺分数自动获得所有高级采掘权限。
- 战斗速度、单次作用和耐用差异受模板预算约束，保持基础攻击节奏与附魔作用可解释；正式增幅要通过试玩决定。
- 修理、磨石、附魔和后续锻造要分别定义组件继承/移除，不能重复施加同一个工艺效果。普通维修不触发重新抽取材料属性。
- 工艺报告属于知识；材料和工具属于实物。复制图纸、修复显示名称或转换物品表示不复制附魔、剩余耐久或材料。

原版下界合金升级已有锻造模板与材料条件；纹饰另有自身定位。本轮工艺不会将这些既有取得条件隐含替换成普通热压。[官方1.20锻造说明](https://feedback.minecraft.net/hc/en-us/articles/16499677456781-Minecraft-Java-Edition-1-20-Trails-Tales)

### 2.3 第一张工具模型卡

比较同批试件/工具在同类目标上的实际结果，控制使用动作和附魔等条件。标签可以是固定工作量后的耐久消耗、合格加工次数和完成时间。早期不必为取样损坏正式工具，可用小试件研究材料规律；真实用途验证仍需实际工具。

第一张卡仅预测某种工序/几何范围内的表现。将配方名作为输入、将作者隐藏材料分作为标签，会让玩家只学到查表；应保存能实际调节和观察的变量。

## 3. 量产模型：任务由真实库存和工序完成

生产作业分为三类，各用原有权威来源：

| 作业类型 | 实际执行者 | 需要记录 |
| --- | --- | --- |
| 原版直接合成 | 相容的原版合成器/配方执行 | 当前配方、槽位、消耗、产物及余物 |
| 模组材料工艺 | 相应工位的有序状态转变 | 实际物料、工序、供给、在制品与用途报告 |
| 实物搬运 | 真实搬运接口/载具/作用装置 | 从何处取出、运输中的实际内容、到何处交付 |

订单进度计已交付到目标库存且符合规格的数量；在制品、预留和运输中物品分别显示。移交的一端满了，库存留在实际所在位置；不能两端同时拥有。原版合成器输出规则仍由原版执行器负责，调度器的停料设计应事先观察出口而不篡改原版输出语义。

对同一任务执行“预计消耗→预留→实际执行→真实产物移交→更新订单”。重读回执不增加交付；多订单共享库存时预留要有唯一归属。取消已加工任务留下真实半成品，只有尚未消耗的预留可释放。

生产改善分别报告单位时间交付、合格率、材料回收与人工干预次数。能量富余后，堵塞、料型混杂和工序争用仍可成为建造问题；不得用通用产量倍率重复记入原料分流与最终配方。

首轮例子是“石质料处理/熔炼→石砖自动合成→仓库备料”，以及“木料/纤维处理→纸类/结构件”。相容Minecraft配方的具体数量按1.21.1实际配方核对，当前不另造一套相矛盾的数量表。原版合成器、红石驱动、余物输出及漏斗交互已有官方定义。[官方1.21说明](https://feedback.minecraft.net/hc/en-us/articles/27547857163917-Minecraft-Java-Edition-1-21-Tricky-Trials)

## 4. 矢量作业：运动与局部材料加工分开求

### 4.1 第一种运动模型

对已支持的载物对象使用游戏有效质量m_eff，来源为对象类别和装载量的登记规则。它是统一的游戏运动预算，不假定Minecraft已有每种物品的真实质量。

```text
Δv = J / m_eff
v_after = v_before + Δv
ΔK = 0.5*m_eff*(|v_after|²-|v_before|²)
```

J来自真实驱动在实际作用窗的力积分；还受峰值力、持续时间、行程、接触、支架和对象允许速度约束。设备输入能量至少覆盖正的ΔK、转换/控制消耗和其他真实变化；负ΔK进入缓冲、热或明确存在的回收机构，不直接退款为无限电力。

源和固定支撑接收对应反作用。上述式子只描述一段受限整体运动更新，不证明任意轨迹、软体接触或离散碰撞已模拟。飞行/运输途中继续遵循实际碰撞和相应世界规则。

### 4.2 可玩自由度逐步展开

首套送料只调方向、源档位、接料面位置；先用同类同装载对象校准。随后改变载荷、节拍或路径，得到“上一档位为什么不再适合”的实验。模型可建议档位，但目标到达由真正经过路径并进入目标接口证明。

区域采掘先限制在固定支架与明确工具头的作业范围，走真实工具/破坏与掉落规则，输出只有一次。移动带库存方块属于后续独立能力，需要位置、内容、连接与装载区一致迁移；早期搬运不默认包含它。

玩家移动设施有可见作用区域和速度/行程模板。服务器规则、世界保护和其他模组实体的适配边界由执行器保留；一个向量模型不自动授予任意对象控制权。

## 5. 环境模型：让观测有来源，让推断有范围

### 5.1 两种数据来源

| 来源 | 可用内容 | 约定 |
| --- | --- | --- |
| 原版状态/事件适配 | 明确开放的方块状态、亮度、天气/时间、相容振动事件等 | 保留原版含义和采集范围；没有适配的状态为未知 |
| 模组环境与主动响应 | 登记热/机械/场源、传递路径、探头与参考、实际激励 | 由共享的局部世界状态生成，多个探针观察同一过程 |

生物群系的分类/背景参数、某个点的测量温度、设备内部温度三者不能混为一个数。原版没有统一营养或连续气候求解的部分，不能伪称探针已经读到；受控设施可以有自身明确模拟的状态。

原版校频感测器的“频率”用于事件类别过滤；适配后保存为事件语义域。它不自动成为机械Hz、光谱坐标或实体身份识别器。振动事件由相应原版接收/遮挡/冷却规则处理，模组物理通道则使用自己的传递模型，不能一份事件两种名义重复计数。[官方振动与共鸣说明](https://feedback.minecraft.net/hc/en-us/articles/16499677456781-Minecraft-Java-Edition-1-20-Trails-Tales)

### 5.2 从环境到读数

```text
y_i(t) = measurement_i(shared_field, pose, path, band, integration_window)
         + instrument_bias_i + measurement_noise_i
```

共享环境包含已登记背景与实际局部源/事件；母批偏差、环境波动、探头误差分开。带相干/非线性关系的源按其对应模型处理，不能一概相加功率或幅值。相同世界过程不会因重新打开GUI而重抽。

记录保存位置/维度、真实采集时段、实际探头和参考、信号域、原始读数、有效性以及后续估计。多点地图保留未测区与分辨率；插值与预测均标为派生内容，不能成为新的实测记录。

### 5.3 第一条环境调查

在工坊内外各布一点，比较送料装置停机/运行，再交换探头位置。若异常随设备开关而变，进一步改变距离或支撑；若随探头走，先校准仪器。首次成果可以是“把参考台移到这个位置”，直接减少后续试验波动。

地层主动探测只对已实现传递/响应的材料族和范围提供候选解释，可能需要实际取样区分。不能将隐藏方块ID直接显示为所谓“频谱推断”。从未知异常到解释是模型研究内容。

## 6. 生物模型：观察原版与管理培养设施各有边界

### 6.1 原版农场从观察和可执行辅助开始

探针记录允许读取的作物阶段、光照/水相关状态、时间与实际管理动作；阶段是离散观察，不等于仪器已测到精确内部生物量。简单设施做补给、灌溉布局、收集与相容收获。

原版生长保持原有机制，模组外的农田不增加一套强制营养/温度维护要求。任何主动促进必须执行明确的、实际消耗资源的动作，不能在原版生长之外每tick无条件再加一次进度或掉落。

### 6.2 受控培养使用显式状态

```text
CultureBatch
  物种/登记培养类型、实际接种体、来源与代次
  生物量B、活性/阶段、容量K、基质与营养N[j]、水W
  环境历程、受支持的响应/变异状态、污染/失效状态
  已收获量、留种份额、实际产物与残料
```

初版培养对象是模组明确登记的植物/菌类/虚构黏弹培养物。种质信息是知识，接种体是实物；普通有机浆不自动含有全部培养类型。遗传/选育若增加，需有限类型、稳定来源与真实后代，不能每开一次GUI刷新特性。

首个候选采用受物料与容量限制的生长步：

```text
potential_growth = r(可测工况、培养类型、当前状态) * B*(1-B/K)*Δt
ΔB = max(0, min(potential_growth, K-B, N[j]/a[j] 对每个必需j, W/a_water))
N[j]_next = N[j] - a[j]*ΔB
W_next = W - a_water*ΔB
B_next = B + ΔB
```

系数a仅对需要消耗的登记物料定义，必须为正。此式仅描述正常生长，要求B≥0、K>0、Δt适当且r有有效范围；死亡、维护消耗、污染和迁移另设过程，不能用一个负r省略残留物去向。必要时细分时间步，结果不以截断掩盖数值错误。

光/供热/机械激励可以改变已登记的速率或条件，但不能代替物料。首个例子取潜在增长5、容量余量3、营养2且每增长消耗0.5、水1且每增长消耗0.25，则实际增长3，剩营养0.5、水0.25。容量或营养成为限制时继续供电不会增加生物量。

### 6.3 收获、留种和原版产物

收获从实际生物量/可收获份额中扣除，按培养类型分为产品、留种、残料和已登记损耗。输出原版物品时遵守明确产物配额；不能在保留全部生物量的同时周期性无限取物。

受控设施若用原版作物外观表示内部进度，该实例只由一个生长控制者更新；不能同时接受完整原版随机生长和设施自定义生长。普通田块与受控实例要有明确转换/收料规则，避免取出重放获得第二次收获。

优先交付纤维、树脂/粘结、颜料、菌类或登记有机前体。黏液/蜂蜡等路线按实际取得的相容培养类型、物料与环境拓展。烈焰/末影等特殊路线需要对应实际物质/作用机制，首次样本的知识解锁不证明一般有机料能完成该转换；它们留作后续研究而不把早期能量充裕变成稀有物免费生成。

### 6.4 频率相关生物玩法怎样成立

先做取样、周期响应和材料性质观察，例如某培养物的黏弹响应、光学粗读数与当前阶段的关系。是否存在特定激励影响生长/分离，是该游戏材料族明确登记的模型，不宣称所有生物都能按一个“生命频率”操控。

同批、空白与处理组比较；区分“更容易分离原有产物”和“产生了更多生物量”。若只改变采收时间或回收率，报告不写成生长速度增加。晶体的意义在激励/观测的可调和可重复。

## 7. 中期模型开发：从实际任务提出数学问题

| 应用任务 | 早期基线 | 第一种中期模型 | 验证方式 |
| --- | --- | --- | --- |
| 工具耐用/工艺合格 | 同批表格与单变量对照 | 多变量回归或受限小网络 | 留出母批及不同允许工况，比较实际工具/试件 |
| 备料与生产 | 固定库存阈值、先到先做 | 消耗预测、队列/工序模型 | 实际交付、断料与库存占用，检查突发订单 |
| 送料 | 固定档位/载荷查表 | 载荷/路径到设置的模型 | 新载荷与真实到达，核对碰撞/堵塞 |
| 环境调查 | 单点参考和源开/关 | 多探头时序/空间模型 | 留出地点/时段，必要时做真实干预 |
| 培育 | 固定温程/补给、单变量拟合 | 生长/产量预测、受限策略 | 按培养批次/时间留出，对比保守控制 |

第一份培养数据可从温度代理、光照、基质可用量与时间/阶段等**实际可得**特征中选取；不同时混淆绝对时间、昼夜相位和采样间隔。标签采用实际到达收获条件的时长或下一窗口实际产量。未完成批次的“尚未收获”不是零耗时，缺测/未完成状态单独保存。

原版作物观察可用离散阶段和管理动作建立另一份数据集；它与受控培养的连续B模型不混训成同一个真值。更换原料族/培养类型/维度或仪器后应检查适用范围。

先将数据按独立批次、田块/设施及时间拆分，避免同一批相邻帧同时进入训练与留出集。归一化与参数拟合只用训练部分，比较均值/规则/回归基线。预测有用不自动证明某个变量是原因，因果解释仍需对照与干预。

可选小网络可复用R4的4→8→2拓扑作为新的应用模型工件，特征、输出、权重和归一化独立登记；不能直接把演示M01的固定权重当成已经训练好的农业模型。相同限定拓扑可参考既有工作集，加入其他状态、预处理或日志后重新核算。

早期固定统计台仍是最多16条的固定分析，工程册负责记录/展示与手工判断。B01提供通用算子和实际训练资源；集群在多地点并发、更多数据/候选和跨设施调度时逐渐有用。小农场和单工位不强制先造集群。

学习策略只提交已有执行口支持的动作，有采样周期、本地控制与失效回退。奖励使用实际可用产物、真实时间/消耗与越界记录，防止靠重复收获回执或永远不结束批次取得虚假高分。

## 8. 本轮边界与原型验收

本轮是应用/模型工作稿，尚未实现原版物品适配、方块搬运、环境场、工具战斗平衡或培养模拟。原型应各自回答：

1. 锻造：同批不同工艺是否产生可理解取舍，合格基础工具是否值得使用，修理/附魔是否保持一致。
2. 量产：真实原料与成品闭合，余物/满仓/取消能处理，订单完成是否确实收到物品。
3. 矢量：有实际作用路径和轨迹，负载/接料影响结果，物品、工具掉落与移动状态只有一份。
4. 探针：同一环境共享真值，区分仪器误差和源，缺少观测时保持未知。
5. 培育：实际输入、有限时间、收获/留种闭合，观察原版与受控模拟无双重生长。
6. 模型：标签可观测、按批留出、基线可用、计算/记录确实占用既有硬件。
