# Kamaen Info 全光计算与光逻辑系统设计

本文档是中游「全光计算」阶段（第 6 阶段）的规范设计参考，定义光控制核、光协处理器、光GPU、光脉冲处理器、光RAM 五件套的架构、工艺、能耗模型，以及与信息系统和后续费曼过程蓝图的物理接续关系。其它文档中涉及光计算的内容均以本文为术语基准。

---

## 1. 设计定位

### 1.1 主题契合

Kamaen Info 的核心是「信息」。光是信息论中最纯粹的载体——Shannon 容量直接由波长和带宽决定，频率本身就是信息。中游引入全光计算收回了早期三处已经画好的伏笔，并打通了从卡玛恩晶体到量子光学费曼过程的完整叙事链：

- **频率协议 F1–F5**：F4 光频协议在第 6 阶段成为全光系统的内部时钟基准
- **三轴晶体的「导波 / 稳谱」属性**：导波 → 光子限域介质（逻辑门和矩阵运算的光路载体）；稳谱 → 光控制核相位基准（FSM 时钟稳定的物质来源）
- **抽象的"相干能"**：落实成维持全光路径相干所需的持续泵浦预算
- **向量爆破中写入的应力张量**：成为卡玛恩晶体二阶光非线性系数 χ⁽²⁾ 的可调参量——第 2–3 阶段的晶体质量直接决定第 6 阶段光逻辑门的开关阈值

### 1.2 现实参照与卡玛恩晶体的突破

| 真实世界 | 模组对应 |
|---------|---------|
| 硅光集成（Silicon Photonics） | 光控制核和光GPU 的底层导光介质 |
| Lightmatter 的 MZI 干涉网络 | 光GPU 架构原型 |
| 铌酸锂电光调制器 | 光逻辑门相位切换原型（但控制信号也是光） |
| 光学双稳态（Optical bistability） | 全光触发器 / 光RAM 晶胞原型 |
| 量子点单光子源、SNSPD | 第 7 / 第 8 阶段产物 |

**真实物理限制与卡玛恩晶体的突破**

真实世界中全光逻辑门的工程挑战在于：光子-光子相互作用极弱（除非借助极强的非线性介质）；光学分支和持久存储代价高。这些正是卡玛恩晶体在游戏世界中弥补的：

```
卡玛恩晶体光非线性机制（游戏设定）：

稳谱晶体 + 应力张量 → 调谐的 χ⁽²⁾ 非线性系数
导波晶体 → 光子限域，增强非线性相互作用路径长度
双轴压缩处理后的晶体 → 光学双稳态条件成立

结果：控制光子可调制信号光子的相位 →
      可构造全光 AND / OR / NOT / XOR 门与光学 FSM
```

第 2–3 阶段对晶体施加的向量爆破和调谐工艺，在第 6 阶段产生直接回报：高品级专化晶体的 χ⁽²⁾ 更大、噪声更低、双稳态阈值更稳定，光逻辑门的保真度随之提升。没有高品级晶体，光控制核会出现随机位翻转；有了高品级晶体，全光系统才具备稳定控制能力。

### 1.3 激发-湮灭：全光逻辑的基本操作周期

全光信息系统的基本信息单元不是电荷的积累，而是光子的激发（激发）与湮灭（湮灭）。

```
完整操作周期：

激发（Excitation）：
  外部光子 → 进入卡玛恩晶体共振腔
  → 晶体声子模式被激活（腔内能量升高）
  等价于：â†|crystal⟩  信息写入晶体

传播（Propagation）：
  已激发的声子模式 → 修改导波中探针光子的折射率
  → 探针光子路径偏转
  逻辑运算在此发生（偏转方向 = 0 或 1）

湮灭（Annihilation）：
  声子模式弛豫 → 定向释放光子
  → 信息从晶体读出并沿波导传播
  等价于：â|crystal*⟩  信息输出

模式复位：
  晶体返回基态 → 等待下一个激发周期
```

这个三步周期直接对应费曼图中的顶点结构：
- 激发 → 吸收顶点（γ_pump + 晶格 → 激发态晶格）
- 湮灭 → 发射顶点（激发态晶格 → γ_out + 晶格基态）
- 传播 → 内线传播子（信息在两个顶点之间传播）

**第 6 阶段的光逻辑门是上述顶点的宏观系综**（大量光子，经典相干）。**第 7–8 阶段的费曼过程蓝图**让玩家在单光子层级处理同一套顶点。两个阶段是同一物理的不同尺度，语言直接延续。

## 3. 工艺链

### 3.1 第 3 阶段铺垫（共振调谐时代）
- 「导波」晶体加工 → 波导原型（粗）；同时是光逻辑门非线性介质的原材料
- 「稳谱」晶体加工 → 相位基准原型；为光控制核时钟储备
- 初级调制器原型（手动相位，固定权重）

### 3.2 第 4 阶段铺垫（光路工艺时代）
- 光刻精密化（短波长曝光）：用于光子器件刻蚀、导波槽、探测结和相位调谐片制造
- 相位调谐器（声光效应版）：调谐信号走光/声学耦合，不把电信号作为信息媒介
- 单频激光源前体：稳谱晶体腔 + F2 晶振泵浦
- **第 4 阶段末期关键工艺**：将稳谱晶体与导波晶体共掺杂 → 卡玛恩非线性介质原型（χ⁽²⁾ 初代）

### 3.3 第 6 阶段核心工艺
- **卡玛恩非线性介质制备**：导波晶体 + 稳谱晶体 → 应力调谐非线性腔体 → 提供 χ⁽²⁾
- **光逻辑门封装**：卡玛恩非线性介质 + 波导 + 分束器 → AND/OR/NOT 门单元
- **卡玛恩双稳态晶胞**：两个耦合卡玛恩共振腔 → 光学双稳态 → 可寻址光存储单元
- **光控制核封装**：光逻辑门阵列 + 双稳态晶胞 + F4 光时钟 → 全光有限状态机
- **光脉冲处理器封装**：饱和吸收卡玛恩腔 + 时分复用波导 → 稀疏激活与非线性算子处理
- **光RAM 封装**：卡玛恩受激辐射循环腔 + 部分反射镜 → 短时光存储（≤ 100 tick）
- **MZI 阵列编织**：N×N Clements 矩形网格（光GPU，工艺不变）
- **单频激光源**：稳谱晶体 + F4 晶振（工艺不变，现在泵浦整个全光系统）
- **光协处理器封装**：全光数据通路 + 光学路由交换机 + 光时钟同步 → 集群互连

## 4. 光控制核（photonic_control_core）

### 4.1 定位
全光有限状态机。承担模型内部的控制流、调度、路由、脚本和 I/O，所有信号路径均为光子。卡玛恩晶体的非线性光学特性使光学分支（IF/ELSE）和光学状态存储（触发器/寄存器）成为游戏内可搭建的结构。

### 4.2 卡玛恩双稳态腔：光逻辑基元

```
双稳态腔结构：
  两个相互耦合的卡玛恩共振腔（ω₁, ω₂）

  写入"1"：
    控制光子激发 ω₁ 超过阈值
    → 系统跃迁到高态（自持续，不需要持续控制光）

  保持"1"：
    高态自持续（双稳态性质）
    → 需要持续泵浦维持稳定（相干能消耗）

  写入"0"：
    反向泵浦 ω₂ → 系统弛豫到低态

  读取：
    探针光子通过 ω₁ → 高态时透过，低态时被相消 → 得到 0/1 输出

结果：卡玛恩双稳态晶胞 = 光学 SR 触发器
```

### 4.3 光逻辑门类型

| 门类型 | 光学实现 | 卡玛恩关键属性 |
|--------|---------|---------------|
| AND | 两路激发同时满足阈值才允许探针通过 | 高阈值 χ⁽²⁾ 腔 |
| OR | 单路激发即允许探针 | 低阈值腔 |
| NOT | 泵浦存在时探针路径被相消干涉 | 反相位调谐（稳谱晶体提供基准）|
| NAND | AND + NOT 串联 | 以上组合 |
| XOR | 两路同时激发时产生相消干涉，不同时激发时通过 | 平衡 MZI + χ⁽²⁾ |

晶体品级影响每个门的：**激发阈值稳定性**（低品级 → 阈值漂移 → 概率性误判）和**响应速率**（低品级 → 激发-湮灭周期变慢 → 时钟频率上限降低）。

### 4.4 光有限状态机（FSM）结构

```
光控制核内部：

  F4 晶振 → 全局光时钟基准
      ↓
  双稳态晶胞阵列 → 状态寄存器（N 个晶胞 = N-bit 状态空间）
      ↓
  光逻辑门阵列 → 组合逻辑（状态转移函数：当前状态 + 输入 → 下一状态）
      ↓
  光路由交换机 → 根据当前状态向外派发光信号（任务调度输出）
```

状态寄存器大小（双稳态晶胞数量）是光控制核配方的可升级项，决定可并行跟踪的任务数。

### 4.5 承担的功能分类

| 操作类型 | 承担方 |
|---------|--------|
| `control_ops`（触发器、FSM、任务调度） | **光控制核** |
| `route_ops`（地址解析、路由转发、包处理） | **光控制核 + 光协处理器** |
| `script_ops`（脚本预处理、数据转换） | **光控制核**（编译后的光逻辑图）|
| `sensor_ops`（采样协调、数据整理） | **光控制核** |
| `io_ops`（存储读写、协议、序列化） | **光控制核 + 光RAM** |

### 4.6 性能画像

| 维度 | 特点 |
|------|------|
| 时钟频率 | F4 晶振上限；高品级稳谱晶体提升上限 |
| 状态深度 | 取决于双稳态晶胞数量（配方可升级）|
| 分支延迟 | 1–3 光时钟周期（短，光速传播）|
| 相干能消耗 | 中等（持续泵浦维持双稳态）|
| 晶体质量依赖 | **高**——低品级晶体导致随机位翻转（逻辑错误率上升）|

## 5. 光协处理器（photonic_coprocessor）

### 5.1 定位
光控制核调度下的可插拔互连模块。不承担控制权，而是负责**光适用的数据通路工作**：高带宽数据搬运、批量预处理、缓存间互连、零拷贝光总线。所有数据路径均为光信号。

### 5.2 内部结构
- **光调度逻辑**：简化版光逻辑门序列，接收光控制核的任务描述符
- **光数据通路**：N 通道并行波导，每通道独立 F4 单频源
- **光路由交换机**：全光 1×N 开关，决定数据进出端口（由光控制核信号控制）

### 5.3 接口
- 上接：光控制核（光信号任务描述符）
- 下接：光GPU（数据 + 权重流）、光脉冲处理器（数据流）、其它光协处理器（集群互连）

### 5.4 操作类型承担

| 操作类型 | 承担方 |
|---------|--------|
| `data_move_ops`（批量光数据搬运） | **光协处理器** |
| `prep_ops`（量化/归一化/转置预处理） | **光协处理器 + 光脉冲处理器** |

### 5.5 性能画像
- 带宽：4–16 通道 × F4 波长峰值（主优势）
- 延迟：光路路由有固定开销（不适合极小批量）
- 相干能消耗：低（短距，波长数少）

## 6. 光GPU（photonic_gpu_unit）

### 6.1 定位
密集线性代数加速器。将矩阵乘法（GEMM）、卷积、FFT 转化为光的酉变换在 MZI 网络中传播完成。

**激发-湮灭视角**：
- 输入端：调制器将数据编码为光子幅度/相位 → **激发** MZI 各节点的相位态
- 传播：光子在 MZI 网络中干涉传播 → 矩阵乘法在干涉过程中自然完成
- 输出端：探测器读出出射光场 → **湮灭** 输出光子，产生下一层输入信号

这与费曼图中多顶点过程完全对应：每个 MZI 交叉节点是一个散射顶点，整个网络是从输入态到输出态的费曼振幅求和。光GPU 的一次完整矩阵推理 = 一条多顶点费曼图的幅度计算。

### 6.2 MZI 网络架构
- 输入端：N 通道单频光，调制器把输入向量 x 编码成幅度/相位
- 中间层：N×N MZI 单元（Clements 矩形拓扑），每个 MZI 由两个 50:50 分束器和一个声光相位调谐器构成
- 输出端：N 通道探针光场 → 注入光控制核或光RAM（信号在光域内直接传递，不转电）
- 数学等价：任意酉矩阵 U 可分解为 MZI 网格实现；非酉矩阵通过 SVD → 两个酉阵 + 对角阵

**外部接口层**：只有在模型推理结果需要输出到游戏世界（影响实体、触发执行器）时，才经过光探测器进行光→数值转换。系统内部所有激活传递均为光信号。

### 6.3 权重写入
- 权重 = MZI 声光调谐器的稳态相位偏置
- 写入：光控制核向相位调谐器发送光信号 → 声光效应调节波导折射率 → 锁定相位
- 一旦写入，推理期不变；切换模型需重新校准（消耗时间 + 相干能突增）

### 6.4 性能画像

| 维度 | 特点 |
|------|------|
| 峰值算力 | 高（每光时钟一次完整矩阵-向量乘法）|
| 延迟 | 单次推理光路传播极短；权重切换代价高 |
| 适用模型 | 固定权重 / 大批量 / 矩阵密集（CNN、Transformer 前向）|
| 不适用 | 分支密集、稀疏权重、快速权重切换、动态算子 |

### 6.5 与光脉冲处理器的分工

| 维度 | 光GPU | 光脉冲处理器 |
|------|-------|------------|
| 数据形态 | 密集张量 | 稀疏 / 脉冲序列 |
| 算子类型 | GEMM / FFT / 卷积 | 激活函数近似 / 稀疏选择 / 脉冲整形 |
| 权重切换 | 慢（重新校准） | 快（调整泵浦功率）|
| 适合场景 | 模型主干 | 模型尾部 / 非线性后处理 |

- 16 × `mzi_modulator`
- 16 × `phase_tuner`（声光效应版）
- 8 × `kamaen_nonlinear_medium`（输入端编码增强）
- 2 × `single_freq_laser_source`
- 1 × `kamaen_oscillator (F4)`
- 1 × 光协处理器接口板（纯光接口）

## 7. 光脉冲处理器（photonic_pulse_processor）

### 7.1 定位
使用卡玛恩晶体脉冲整形技术处理光GPU 不擅长的部分：稀疏激活（阈值选择）、非线性激活函数近似（S 型传输曲线）、低精度时分复用信号处理。它是全光结构中的非线性/稀疏算子节点，媒介始终是光信号。

### 7.2 卡玛恩脉冲整形机制

```
脉冲整形流程：

输入光子脉冲序列（时分复用）
→ 卡玛恩饱和吸收体腔
    强脉冲（> 阈值）：腔体达到增益漂白态 → 光子透过（高态）
    弱脉冲（< 阈值）：腔体未漂白 → 光子被湮灭（低态）
    → 实现稀疏激活（ReLU 近似）
→ 相位整形腔（卡玛恩 S 型传输曲线）
    → 近似 Sigmoid / Tanh / GELU
→ 输出脉冲序列 → 注入光控制核或光GPU
```

**激发-湮灭视角**：
- 强输入光子 → 激发饱和吸收体到漂白态 → 后续光子透过（激发开路）
- 弱输入光子 → 激发不足阈值 → 腔体将光子湮灭（信息被抑制）
- 这是"一个光子决定下一批光子能否通过"的机制 → 隐含 AND 逻辑，是光脉冲处理器的核心光学原理

### 7.3 承担的功能分类

| 操作类型 | 承担方 |
|---------|--------|
| `sparse_ops`（稀疏激活选择） | **光脉冲处理器** |
| `nonlinear_ops`（激活函数近似） | **光脉冲处理器** |
| `pulse_ops`（脉冲整形、时分多路） | **光脉冲处理器** |
| `quant_ops`（低精度时分信号处理） | **光脉冲处理器** |

### 7.4 性能画像

| 维度 | 特点 |
|------|------|

## 8. 光RAM（photonic_ram_unit）

### 8.1 定位
全光系统的短时状态存储。基于卡玛恩晶体受激辐射循环腔：光子在腔体内循环，每次经过增益区段得到补偿，直到被读取（部分反射镜耦合输出）或被强制清除（反相泵浦）。

光RAM 是激活缓存和状态寄存器，不是持久数据库。超出腔体相干时间后，信息因损耗自然湮灭——这不是缺陷，而是与"激活生命周期"匹配的设计。

### 8.2 激发-湮灭视角

```
写入（激发）：
  输入光子 → 进入循环腔 → 受激辐射维持
  → 信息以光子形式在腔内持续存在

保持（传播）：
  增益介质持续补偿腔内损耗
  → 信息在时间中延续（有寿命上限）

读取（受控湮灭）：
  部分反射镜耦合输出 → 每次读取取出少量光子
  → 多次读取后腔内光子逐渐湮灭（读取衰减）

清除（强制湮灭）：
  反相泵浦 → 相消干涉 → 腔内光子迅速湮灭 → 写入"0"
```

光RAM 的每次读取都消耗一部分腔内光子——这是游戏中光信息系统"读取有代价"的实现，也直接对应量子力学中测量对态的扰动（为第 7–8 阶段量子光学做认知铺垫）。

### 8.3 容量与寿命

| 参数 | 典型值 |
|------|--------|
| 每单元循环腔数 | 4–16 条（配方决定）|
| 每腔存储量 | 1 bit（强/弱循环功率）|
| 寿命 | 20–80 tick（晶体品级和温度影响）|
| 读取衰减 | 每次读取取出约 5–10% 腔内光子 |
| 刷新机制 | 光控制核周期性重写高价值状态 |

### 8.4 读取衰减基准曲线

第一版实现使用“随时间线性衰减 + 随读取次数乘法衰减”的简化模型，避免服务端模拟连续光场。

```text
age_factor = clamp(1 - age_ticks / ram_coherence_life, 0, 1)
read_factor = (1 - read_decay_rate) ^ read_count
effective_strength = stored_strength * age_factor * read_factor
```

默认阈值：

| `effective_strength` | 状态 |
| --- | --- |
| `>= 0.65` | 稳定读取，无惩罚 |
| `0.35–0.65` | 弱读取，输出质量下降 |
| `0.15–0.35` | 噪声读取，可能触发错误重试 |
| `< 0.15` | 状态丢失，视为未命中或清零 |

按晶体品级给出初始平衡值：

| 品级 | `ram_coherence_life` | `read_decay_rate` | 建议刷新周期 |
| --- | --- | --- | --- |
| 粗制 | 20 tick | 0.10 | 8–10 tick |
| 稳定 | 40 tick | 0.075 | 16–20 tick |
| 调谐 | 80 tick | 0.05 | 32–40 tick |

调参原则：低品级光RAM 应明显适合短链路、低读取次数和低频状态；高品级光RAM 才能支撑 recurrent state、反馈回路和多节点共享状态。若测试中玩家频繁因状态丢失而无法定位问题，优先提高诊断提示和刷新建议，而不是直接取消衰减。

## 9. 相干能（coherent_energy）模型

### 9.1 物理意义
维持全光逻辑路径相干所需的能量。来自单频激光源的持续泵浦消耗。**不是 FE 的子类，是独立资源**——在 UI 中单独显示。

全光架构下，相干能消耗有两层来源：
1. **光逻辑层**：光控制核和光脉冲处理器的双稳态腔与非线性腔维持泵浦
2. **光矩阵层**：光GPU 的 MZI 网络相位稳定和锁相泵浦

### 9.2 消耗公式（扩展版）

```
coherent_cost =
  logic_cost × gate_count × crystal_quality_factor
  + matrix_cost × mzi_count × temperature_factor × wavelength_count × duty
```

| 项 | 含义 | 典型范围 |
|---|------|---------|
| logic_cost | 每个光逻辑门/双稳态晶胞的基础维持成本 | 0.3 单位 / tick / 门 |
| gate_count | 光控制核中激活门数量 | 8 – 64 |
| crystal_quality_factor | 晶体品级倒数系数：低品级耗散更多 | 1.0（高品级）~ 3.0（低品级）|
| matrix_cost | 每 MZI 基础成本 | 1 单位 / tick / MZI |
| temperature_factor | 温度系数 | 1.0（理想）~ 2.5（高负载）|
| wavelength_count | 同时锁相的波长数 | 1 – 8 |
| duty | 占空比 | 0.1 – 1.0 |

### 9.3 失稳后果

| 相干度 | 光逻辑层后果 | 光矩阵层后果 |
|--------|------------|------------|
| 70–100% | 正常 | 正常 |
| 50–70% | 光控制核出现概率性位翻转（任务调度偶发异常）；光脉冲处理器阈值轻微漂移 | 轻微数值噪声 |
| 30–50% | 逻辑错误率显著上升，调度混乱 | 推理精度下降，结果标记 invalid |
| < 30% | 全光系统进入"光路崩溃"，所有组件暂停 | 同左 |

### 9.4 恢复手段
- 「光路再校准」工艺：消耗 1 `calibration_token` + 60 秒 + 相干能突增
- 加强冷却（降低 temperature_factor）
- 降负载（减少 gate_count 和 wavelength_count）
- 提升晶体品级（降低 crystal_quality_factor）

### 9.5 与稳谱晶体的关系
稳谱晶体是相干能产生效率的关键。高品级稳谱晶体的激光源效率高，相同相干能消耗下输出更强的泵浦。第 7 阶段引入单光子源后，可进入更高效率档。

## 13. 与费曼蓝图的协作（核心接续章节）

### 13.1 阶段连续性：宏观 → 中观 → 量子

第 6 阶段全光系统与第 7–8 阶段费曼过程蓝图使用**相同的基础物理**，只是观测尺度不同：

```
第 6 阶段（宏观系综）：
  光控制核中的双稳态腔
  → 每个时钟周期：大量光子集体激发 / 湮灭
  → 宏观信号（0/1）= 整个光子系综的统计均值

第 7 阶段（中观费曼）：
  费曼过程蓝图中的光-晶格相互作用顶点
  → 玩家绘制：γ_pump + |lattice⟩ → |excited_lattice⟩ → γ_out + |lattice⟩
  → 这正是第 6 阶段光逻辑门的单光子描述

第 8 阶段（量子光学）：
  单光子源 + SNSPD + 线性光路 + 后选择测量
  → 玻色采样协处理器
  → 叠加态被利用，不再是经典确定性信息
```

玩家在第 7 阶段画费曼图时，可以认出这些顶点——它们就是自己在第 6 阶段每天运行的光逻辑门里发生的事。

### 13.2 光GPU 的费曼图诠释

光GPU 的一次矩阵-向量乘法是一条多顶点费曼图的幅度计算：
- 每个 MZI 交叉节点 = 散射顶点（光子-光子间接作用，通过卡玛恩非线性介质媒介）
- 每条波导段 = 传播子（内线）
- 整个 MZI 网络 = 从输入态 |x⟩ 到输出态 |Ux⟩ 的振幅求和

第 7 阶段费曼过程蓝图：
- 费曼图的振幅求和 = 路径积分 = 矩阵乘法 → 由光GPU 加速计算
- 光控制核负责派发费曼图的顶点顺序和路径选择
- 光脉冲处理器负责非线性顶点（如光子自相互作用）的函数近似

### 13.3 术语统一（第 6 阶段 → 第 7 阶段）

1. 至少 1 台 `photonic_control_core` 持续运行 ≥ 10 分钟，逻辑错误率 < 1%

3. 至少 1 台 `photonic_pulse_processor` 处理光GPU 输出并正确输出激活值
4. 至少 1 台 `photonic_ram_unit` 维持 State 存储 ≥ 20 tick 不丢失
5. 相干能产生与消耗达到稳态平衡（持续 5 分钟无失稳）
6. 在诊断台打开费曼描述模式，确认至少一个组件显示出费曼图标注（为第 7 阶段做认知铺垫）
